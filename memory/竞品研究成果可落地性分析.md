## 一、可直接复用的成果（按优先级）

### 🔴 P0 — 拿来即用（直接对标漫舟）

#### 1. CDP JSON Schema（联易方舟）
**来源**：`联易方舟-漫剧制作底层架构深度研究.md`
**状态**：完整Schema + 8镜头真实数据 + 8角色 + 8场景 + 30道具

**可直接复用的字段结构**：

```json
{
  "meta": { "sourceType", "append", "chapters[]" },
  "settings": { "targetPlatform", "aspectRatio", "stylePreset", "shotDurationSec", "episodeDurationMin" },
  "characters": [{ "id", "name", "aliases[]", "gender", "age", "appearance", "clothing", "persona" }],
  "locations": [{ "id", "name", "description", "props[]" }],
  "items": [{ "id", "name", "description", "appearance" }],
  "shots": [{
    "id", "shotNumber", "durationSec",
    "locationId", "characterIds[]", "itemIds[]",
    "script", "dialogue[]", "imagePrompt", "videoPrompt",
    "objective", "action", "reference"
  }]
}
```

**对漫舟的优化价值**：
- 镜头时长从"范围"→固定秒数（联易方舟用固定15s）
- 角色从"文本名"→ID引用（`characterIds[]`）
- 场景从"文本名"→ID引用（`locationId`）
- 新增道具系统（漫舟目前缺失）

#### 2. 增量追加机制（联易方舟）
**来源**：同上
```javascript
existingCharactersJson / existingLocationsJson / existingItemsJson
meta.append = true
shotNumber 从1开始（系统自动偏移）
```
**价值**：支持多章节/多集制作，是漫舟做第02集的核心机制

#### 3. 4个CDP改编Prompt模板（联易方舟）
| 模板 | 用途 | 参数 |
|------|------|------|
| 标准15S版 | 一键改编 | temp=0.7, maxTokens=50K |
| 脚本分镜15S | 分镜细化 | temp=0.8, maxTokens=50K |
| Sora2/Grok专用 | 视频模型适配 | temp=0.8 |
| Veo 8S版 | 短镜头 | temp=0.7 |

**价值**：可直接作为漫舟 `manzhou-script` 和 `manzhou-storyboard` 的Prompt增强参考

#### 3b. 3个原创剧本Prompt模板（联易方舟·之前遗漏）
| 模板 | 用途 | 核心复用点 |
|------|------|-----------|
| **剧本创意** | 题材/情绪/角色设定 → N条差异化创意 | 差异化规则（至少一项不同）；严格JSON约束 |
| **剧本大纲** | 创意 → 总大纲 + 人物小传 | hook≤30字；每5集小高潮/10集大反转 |
| **剧本正文** | 大纲 → 分场景剧本正文 | 开场5秒抓人；台词≤15字；@引用变量机制 |

**漫舟现状**：`manzhou-script` 从IP解析直接到三维剧本，缺失"先创意→后大纲"的二级结构
**可落地**：增加 `manzhou-concept` 和 `manzhou-outline` 两个前置Skill

#### 4. 5个资产生成Prompt模板（联易方舟）
| 模板 | 对应漫舟Skill |
|------|-------------|
| 角色卡单图 | manzhou-character-consistency |
| 角色三视图 | manzhou-character-consistency（2x2网格） |
| 面部特写单图 | manzhou-character-consistency |
| 场景基底图 | manzhou-visual-style |
| 道具/物品图 | **漫舟缺失此功能** |

#### 5. 九宫格分镜Prompt（联易方舟）
**格式**：3x3网格，单张2K图片
**每格标签**：`1-远景/2-全景/3-中景/4-近景/5-特写/6-大特写/7-低角度/8-高角度/9-俯视`
**硬约束**：禁止任何文字/英文/水印

**对比漫舟九宫格**：联易方舟更精细（3x3固定标签），漫舟的更灵活

#### 6. 11种风格预设（联易方舟）
`anime / cn_anime / cn_3d / ink / cyber / us_comics / real / horror / pixar / shinkai / miyazaki`
**每种有完整描述文本**，可直接填充到 `manzhou-visual-style.md`

### 🟡 P1 — 增强复用（提升漫舟能力边界）

#### 7. 5灯灯光体系（NanoPhoto → TapNow）
```
key light    — 主光（塑造形态）
rim light   — 轮廓光（分离主体）
fill light  — 补光（减少阴影）
kicker light — 强化轮廓
negative fill — 负补光（加深阴影）
```
**漫舟现状**：视觉风格中隐含灯光描述，但无独立体系
**可落地**：增加独立"灯光设定"字段，注入到 image_prompt

#### 8. videoPrompt Sora2格式（联易方舟）
```
Global Context（no text/no subtitles/no music）
Shot 1 / Duration: X sec / Scene: [描述]
Shot 2 / Duration: X sec / Scene: [描述]
各Shot Duration之和 ≈ durationSec（±1秒）
```
**漫舟现状**：只有单段 video_prompt
**可落地**：升级为多Shot格式，支持更长镜头（15s/25s）的镜头分段

#### 9. 分镜14列Schema（TapNow）
| 字段 | 漫舟现状 |
|------|---------|
| 镜号/时长/分镜描述/景别/角度/运镜/场景标签 | manzhou-storyboard已有 |
| 镜头类型枚举 | 可直接复用 |
| 相机角度枚举 | 可直接复用 |
| 运镜方式枚举 | 可直接复用 |

#### 10. 镜头边界检测 + 帧提取策略（TapNow）
**发现**：TapNow实测 = 30帧/134秒（≈每4秒1帧）
**漫舟现状**：无视频分析能力
**缺口**：镜头边界检测算法未公开，但帧提取策略可直接参考

## 四、核心结论

```
【LibTV】→ ❌ 无可复用，纯展示层
【联易方舟】→ 🔴 P0级，CDP Schema + Prompt模板可直接落地
【TapNow】→ 🟡 P1-P2级，分镜Prompt + 5步法模板增强漫舟
【NanoPhoto】→ 🟢 P2级，10+维度体系扩展设计视野
【漫舟】→ ✅ 全链路覆盖，竞品研究加速P0-P3迭代
```

**最重要的发现**：
1. **联易方舟的CDP JSON是业界最完整的漫剧数据结构** — 直接采用作为漫舟标准资产包格式
2. **联易方舟的增量追加机制** — 是漫舟多集制作的关键缺失功能
3. **TapNow的5步分镜法** — 比漫舟现有分镜Prompt更结构化
4. **NanoPhoto的10+维度** — 漫舟音频（VO/BGM/SFX）已是独家优势，可优先保持；视觉维度（灯光/焦段/景深）可逐步补全
