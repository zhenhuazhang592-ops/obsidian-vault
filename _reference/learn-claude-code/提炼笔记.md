## 一、六大核心设计模式

### s01 Agent Loop — 模型驱动循环

只要一个 `while True + stop_reason`，模型决定何时行动、何时停止。

```python
while True:
    response = client.messages.create(model=MODEL, messages=messages, tools=TOOLS)
    messages.append({"role": "assistant", "content": response.content})

    if response.stop_reason != "tool_use":
        return  # 模型说停就停

    results = []
    for block in response.content:
        if block.type == "tool_use":
            output = TOOL_HANDLERS[block.name](**block.input)
            results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
    messages.append({"role": "user", "content": results})
```

- Agent Loop 是通用骨架，工具再多循环不变
- `stop_reason` 是模型自主性的核心——不是代码在控制，是模型在决策

---

### s02 Tool Use — 工具注册机制

新工具只加 handler，循环零改动。

```python
TOOL_HANDLERS = {
    "bash":       lambda **kw: run_bash(kw["command"]),
    "read_file":  lambda **kw: run_read(kw["path"]),
    "write_file": lambda **kw: run_write(kw["path"], kw["content"]),
}

TOOLS = [
    {"name": "bash", "description": "Run shell command",
     "input_schema": {"type": "object", "properties": {"command": {"type": "string"}}, "required": ["command"]}},
]
```

- 工具是原子的、可组合的
- 危险命令拦截：检查黑名单

### s04 Subagent — 上下文隔离

子代理用独立 `messages[]`，只返回摘要，父上下文保持干净。

```python
def run_subagent(prompt: str) -> str:
    sub_messages = [{"role": "user", "content": prompt}]  # 全新上下文
    for _ in range(30):  # 安全限制
        response = client.messages.create(model=MODEL, system=SUBAGENT_SYSTEM,
                                          messages=sub_messages, tools=CHILD_TOOLS)
        # ... 执行工具 ...
    return "".join(b.text for b in response.content if hasattr(b, "text"))
```

- 探索任务拆给子代理，避免污染主上下文
- 子代理没有 task 工具（禁止递归）
- 进程隔离 = 上下文隔离

### s05 Skill Loading — 两层知识注入

- **Layer 1**：system prompt 放 metadata（~100 tokens/skill，模型知道有哪些可用）
- **Layer 2**：模型调用 `load_skill` 时，通过 tool_result 返回完整内容

```python
SYSTEM = f"""Skills available:
  - pdf: Process PDF files...
  - code-review: Review code...
"""
```

Skill 文件格式：

```markdown
# skills/<name>/SKILL.md
---
name: code-review
description: Perform thorough code reviews...
tags: optional, comma, separated
---

# Code Review Skill
## Review Checklist
1. Security (Critical)...
```

- 知识不是塞进 system prompt，是模型"问到时"才给
- Skill 可以包含子目录 (references/、scripts/)

### s07 Task System — 持久化 DAG 任务图

任务持久化为 JSON，依赖关系实现自动解锁。

```python
# .tasks/task_1.json
{"id": 1, "subject": "Write script", "status": "pending", "blockedBy": [], "owner": ""}

def _clear_dependency(self, completed_id):
    for f in self.dir.glob("task_*.json"):
        task = json.loads(f.read_text())
        if completed_id in task.get("blockedBy", []):
            task["blockedBy"].remove(completed_id)
            self._save(task)
```

- DAG 任务图：并行可执行、顺序有依赖、状态跨会话存活
- 持久化到 `.tasks/` 目录，上下文压缩不丢失
- 是 s08-s12 所有机制的协调骨架

### s12 Worktree Isolation — 目录级并行

任务管目标，worktree 管目录，按 ID 绑定。

```python
# Task 绑定 worktree
TASKS.bind_worktree(task_id=1, worktree="ep01-script")

# Worktree 创建
git worktree add -b wt/ep01-script .worktrees/ep01-script HEAD

# 事件流
EVENTS.emit("worktree.create.after", task={"id": 1}, worktree={"name": "ep01-script"})
```

- 控制平面 (Task) + 执行平面 (Worktree) 分离
- 每个任务独立目录，git 分支隔离
- 生命周期事件可审计

## 二、与漫剧创作工坊的结合点

| 漫剧创作痛点 | Harness 模式 | 具体应用 |
|------------|-------------|---------|
| 多集并行开发，配置互相污染 | s12 Worktree 隔离 | 每集一个 worktree：`ep01-script`、`ep02-storyboard` |
| 长剧集上下文爆炸 | s04 Subagent | 分集写脚本、生成配乐各一个子代理，结果摘要返回 |
| 创作流程规范难传承 | s05 Skill 加载 | 固化"漫剧剧本规范 Skill"、"分镜设计 Skill" |
| 大目标(整季)中途断档 | s07 Task 图 | 季任务 -> 集任务 -> 场景任务，带依赖持久化 |
| 多种工具调用 | s02 Dispatch | 脚本读写、视频生成 API、音频处理、Remotion 编译 |

**漫剧创作 Harness 设计草案**：

```
漫剧创作 Harness =
  工具：read/write script, generate audio, call remotion, call image-gen
  技能：script-format-skill, storyboard-skill, voice-clone-skill
  任务：季任务图 → 集任务 → 场景任务 (JSON 持久化)
  隔离：每集 worktree (ep01/, ep02/, ...)
  团队：导演 Agent + 编剧 Agent + 配乐 Agent
```

## 三、建议固化为 Vault Rules 的原则

### 1. 状态持久化原则
> **任务状态必须落在磁盘上，不在内存里。**

```
MEMORY.md = 当前会话仪表盘 (内存，等效 messages[])
.tasks/   = 持久化任务图 (磁盘，等效外部存储)
```

### 2. 上下文隔离原则
> **探索性任务用子代理，结果摘要进主上下文。**

- 调用子代理处理：研究工具链、研究风格参考、批量文件分析
- 子代理中间过程不进入主对话

### 3. 知识按需加载原则
> **Skill 是知识单元，不是系统提示的一部分。**

- vault rules 写在 `.claude/rules/` 下（等效 SKILL.md）
- 模型只知道有哪些 rule（Layer 1），用到时加载完整内容（Layer 2）

### 4. 工具原子化原则
> **每个工具做一件事，通过组合生成复杂行为。**

### 5. 任务图驱动原则
> **大目标必须拆成任务图，不是写进一个 TODO。**

```
MEMORY.md 仪表盘引用 .tasks/ 的当前任务
任务之间用 blockedBy 表达依赖
任务完成自动解锁后续
```

### 6. 目录隔离原则
> **并行工作用 worktree，任务 ID 绑定目录。**
