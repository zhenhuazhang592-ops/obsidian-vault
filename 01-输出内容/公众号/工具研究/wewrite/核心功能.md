# WeWrite 核心功能详解

> 来源：wewrite-main/SKILL.md 执行流程部分

## 8 步完整流程

```
Step 1: 确定客户
Step 2: 热点抓取
Step 2.5: 历史读取 + SEO 数据
Step 3: 选题生成
Step 3.5: 框架选择
Step 4: 文章写作
Step 5: SEO 优化 + 去AI痕迹
Step 6: 视觉AI（封面 + 内文配图）
Step 7: 排版 + 推送草稿
Step 7.5: 写入历史
Step 8: 回复用户
```

---

## Step 1: 确定客户

从用户消息中提取客户名称，读取配置：

```
clients/{client}/style.yaml
```

如果客户目录不存在，提示用户参考 `references/style-template.md` 创建配置。

从 `style.yaml` 中提取：`topics`、`tone`、`voice`、`blacklist`、`theme`、`cover_style`、`author`、`content_style`。

**如果用户直接给了选题**（如"写一篇关于 AI Agent 的公众号文章"），跳过 Step 2-3，直接进入 Step 3.5。

---

## Step 2: 热点抓取

```bash
python3 scripts/fetch_hotspots.py --limit 30
```

脚本返回 JSON，包含多平台热点（微博、头条、百度）。为每条热点标注所属领域和可创作性评分（1-10）。

**降级**：如果脚本报错或返回空列表，用 WebSearch 搜索 "今日热点 {topics中的第一个垂类}"。

---

## Step 2.5: 历史读取 + SEO 数据

读取 `clients/{client}/history.yaml`，提取已发布文章的 topic_keywords，用于 Step 3 去重。

如果 history.yaml 中有带 stats 的文章，提取表现最好的文章特征（框架类型、标题风格），作为偏好参考。

然后对热点中的关键词做 SEO 评分：

```bash
python3 scripts/seo_keywords.py --json {从热点标题中提取的3-5个关键词}
```

---

## Step 3: 选题生成

按 `references/topic-selection.md` 的评估规则生成 10 个选题，每个含标题、评分、点击率潜力、SEO 友好度、推荐框架。

**去重**：对比 history.yaml 中的 topic_keywords，如果某个选题的核心关键词在最近 7 天内已写过，降低评分或标注"近期已覆盖"。

- **自动模式（默认）**：直接选综合评分最高的，继续。
- **交互模式**：输出 10 个选题，等用户选择。

---

## Step 3.5: 框架选择

按 `references/frameworks.md` 为选定的选题生成 5 套框架（痛点型/故事型/清单型/对比型/热点解读型）。

- **自动模式（默认）**：直接选推荐指数最高的框架，继续。
- **交互模式**：输出 5 套框架，等用户选择。

---

## Step 4: 文章写作

按选定框架 + `references/writing-guide.md` 规范写文章：
- H1 标题（20-28 字，converter 自动提取为微信标题）
- 字数 1500-2500
- 按框架大纲组织结构，在金句落点放精炼总结句
- 不插配图占位符（Step 6 自动分析插入）
- 风格遵循 style.yaml 的 tone、voice、content_style
- 避开 blacklist

**Playbook 优先**：如果 `playbook.md` 存在，其中的规则优先于 `writing-guide.md` 的通用规则。

保存到 `output/{client}/{date}-{slug}.md`

---

## Step 5: SEO 优化 + 去AI痕迹

对初稿执行：
1. 生成 3 个备选标题（20-28 字），标注策略
2. 优化关键词密度
3. 去AI痕迹
4. 生成摘要（≤ 54 个中文字）
5. 推荐 5 个精准标签
6. 完读率优化

覆盖保存终稿。自动模式下选评分最高的标题作为最终标题。

---

## Step 6: 视觉AI

### 6a. 分析文章 + 生成提示词

读取终稿，分析结构：
- 提取 H2 标题和各论点段落
- 逐个论点判断是否需要配图（数据/场景/转折处优先，纯观点段可不配）
- 确定配图位置和画面描述
- 约束：总数 3-6 张，间隔≥300字，不在开头和 CTA 处配图

生成封面 3 组创意（直觉冲击/氛围渲染/信息图表）+ 内文配图提示词。

- **自动模式（默认）**：直接用创意 A 作为封面，全部配图直接生成，不停顿。
- **交互模式**：输出方案，等用户确认或调整。

将占位符 `![配图：场景描述](placeholder)` 插入 Markdown。

### 6b. 自动生图

```bash
# 封面（2.35:1 微信封面比例）
python3 toolkit/image_gen.py \
  --prompt "{封面提示词}" \
  --output output/{client}/{date}-cover.png \
  --size cover

# 内文配图（16:9 横版）
python3 toolkit/image_gen.py \
  --prompt "{配图提示词}" \
  --output output/{client}/{date}-img{序号}.png \
  --size article
```

可通过 `--provider` 覆盖默认 provider（doubao/openai）。

**降级**：如果 image_gen.py 报错，输出提示词供用户自行生成，继续后续步骤。

---

## Step 7: 排版 + 推送草稿

```bash
python3 toolkit/cli.py publish {markdown_path} \
  --cover {cover_path} \
  --theme {style.yaml 的 theme} \
  --title "{最终标题}"
```

**降级**：如果 publish 失败，改用 preview：

```bash
python3 toolkit/cli.py preview {markdown_path} \
  --theme {theme} --no-open -o {output_dir}/{slug}.html
```
告知用户本地 HTML 路径。

---

## Step 7.5: 写入历史

发布成功后，向 `clients/{client}/history.yaml` 追加一条记录：

```yaml
- date: "{今天日期}"
  title: "{最终标题}"
  topic_source: "热点抓取"
  topic_keywords: ["{关键词1}", "{关键词2}"]
  framework: "{使用的框架类型}"
  word_count: {字数}
  media_id: "{media_id}"
  stats: null  # 由 fetch_stats.py 后续回填
```

---

## Step 8: 回复用户

**成功**：
- 最终标题 + 2 个备选标题
- 摘要
- 5 个推荐标签
- media_id
- 提醒：请到公众号后台草稿箱检查并发布

**部分成功**：
- 列出每步状态（成功/跳过/失败）
- 附上本地文件路径
- 说明哪些需要用户手动完成

---

## 交互指令（Step 8 后）

用户可以继续要求：
- "帮我润色/缩写/扩写/换语气" → 编辑文章
- "封面换暖色调" → 修改提示词，重新生图
- "第 3 张配图不要了" → 调整 Markdown
- "用框架 B 重写" → 回到 Step 4
- "换一个选题" → 回到 Step 3 展示选题列表
- "看看文章数据" → 执行效果复盘

---

## 错误处理

不要因为任何一步失败就停止整个流程。

| 步骤 | 降级 |
|------|------|
| 热点抓取失败 | WebSearch 替代 |
| 选题为空 | 请用户手动给选题 |
| SEO 关键词查询失败 | 回退到 LLM 判断 |
| 封面生成失败 | 输出提示词，用户自行生成 |
| 推送失败 | 生成本地 HTML，手动操作 |
| 历史写入失败 | 警告但不阻断流程 |
| 效果数据拉取失败 | 告知用户可能需要等 24h |
| Playbook 不存在 | 正常——用 writing-guide.md 通用规则 |
