# 漫舟 vs 智剧通(ZJT) · 短剧制作流程对比分析

> **分析日期**: 2026-03-25
> **分析目的**: 对齐两个系统的制作环节，找出各环节的差距与借鉴点

---

## 二、逐环节深度对比

### 环节 1：输入与初始化

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **输入形态** | 小说文本/IP名称 | 剧本文本/空白画布 | 漫舟更自动化 |
| **初始化配置** | Step0强制选择16种风格/画幅/时长 | 画布自由拖拽，无固定模板 | ZJT更灵活 |
| **世界观管理** | 单一项目，无world概念 | WorldModel完整世界管理体系 | **ZJT领先** |
| **项目隔离** | Markdown目录隔离 | MySQL user_id + world_id双隔离 | **ZJT领先** |
| **会话管理** | 无会话，无历史状态 | ChatSession内存存储+SSE流 | **ZJT领先** |
| **多集管理** | 目录分集（01/02/...） | episode_number字段+分页查询 | 持平 |

### 环节 2：剧本解析

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **解析方式** | LLM指令Prompt（manzhou-shot-script.md） | parse_script_to_shots() 代码引擎（1100行） | ZJT更工程化 |
| **输出格式** | Markdown+8字段 | JSON结构化 | ZJT更机器友好 |
| **180度轴线** | ❌ 无 | **强制执行** ⭐ | **ZJT独有** |
| **多人对话拆分** | ❌ 无，合并描写 | **强制拆分，每角色独立镜头** ⭐ | **ZJT独有** |
| **旁白模式** | 无 | **narration_as_dialogue** ⭐ | ZJT独有 |
| **强制中景** | 无 | **force_medium_shot**（对话镜头禁止全景）⭐ | ZJT独有 |
| **时长重组** | 固定15s/镜，无分组 | **贪心分组算法**（max_group_duration）⭐ | ZJT更智能 |
| **镜头时长建议** | 特写2-5s/全景5-10s（ZJT有）| ❌ 漫舟无精细建议 | ZJT更细 |
| **JSON截断修复** | ❌ 无 | **三层修复机制** ⭐ | ZJT独有 |
| **日志系统** | ❌ 无 | **9种日志文件**（时间戳_步骤_内容）⭐ | ZJT独有 |
| **镜头格式** | P01/P02（Shot Number） | shot_number数字 | 漫舟更直观 |

### 环节 3：角色系统

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **角色引用** | `[ID: char_01]` | `【【角色名】】` ⭐ | ZJT更标准 |
| **外貌一致性** | DNA锚点描述（Prompt） | **严禁外貌进分镜**（强制分离）⭐ | ZJT更强制 |
| **参考图管理** | Prompt拼接，无持久化 | reference_image URL持久化+API查询 ⭐ | ZJT更可靠 |
| **DNA体系** | 6层锚点（身份/外貌/服装/表情/动作/视角）⭐ | appearance+behavior分离 | **漫舟更细** |
| **别名映射** | aliases[]数组 | 角色库匹配 | 持平 |
| **情感音色** | emotion_voices JSON | emotion_voices JSON + 4种情感控制 | ZJT更完整 |
| **角色标记自动解析** | ❌ 无 | **前端解析【【】】→ API查询参考图** ⭐ | ZJT独有 |

### 环节 4：场景与道具

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **场景结构** | 扁平场景列表 | **树形结构（parent_id）** ⭐ | ZJT更结构化 |
| **场景关联** | 无数据库关联 | **location_db_id强制校验** ⭐ | ZJT更严格 |
| **道具关联** | ❌ 无 | **props_db_id强制校验** ⭐ | ZJT更严格 |
| **场景参考图** | moodBoard字段，无持久化 | reference_image URL持久化 | ZJT更可靠 |
| **道具参考图** | 无参考图字段 | reference_image URL持久化 | ZJT更完整 |
| **光影规格** | 场景设计中含光影描述 ⭐ | 无独立光影规格 | **漫舟更细** |

### 环节 5：分镜图生成

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **九宫格生图** | **九宫格分镜图Prompt（3×3）** ⭐ | 无原生九宫格 | **漫舟独有** |
| **宫格拆分/合并** | Prompt中描述 | **宫格拆分算法+合并** ⭐ | ZJT更工程化 |
| **参考图收集** | 手动拼接进Prompt | **节点连线→自动API收集** ⭐ | ZJT更智能 |
| **相机描述** | Prompt中手动写 | **yaw/dolly/pitch→中文Prompt自动转换** ⭐ | ZJT更自动化 |
| **单张参考图** | 单张分镜图Prompt ⭐ | 分镜节点独立生成 | 持平 |
| **生图驱动** | 即梦/SD/MJ（待集成） | Gemini/Seedream（已集成）⭐ | ZJT更完整 |
| **前端可视化** | ❌ 无 | **Canvas+SVG双层渲染** ⭐ | ZJT完整 |

### 环节 6：视频生成

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **驱动架构** | Prompt拼接（待工程化） | **三层工厂模式（Business/Impl/Vendor）** ⭐ | ZJT更工程化 |
| **供应商数量** | 即梦/可灵/海螺（待集成） | **7种（Sora2/Kling/Vidu/VEO3/LTX2/Wan2.2/数字人）** ⭐ | ZJT大幅领先 |
| **图片模式** | 固定首尾帧 | **三种模式（首尾/多参考/混合）** ⭐ | ZJT完整 |
| **首尾帧注入** | --cref参考图引用 ⭐ | reference_image+first_frame_url ⭐ | 持平 |
| **多参考图** | ❌ 无 | **最多3张参考图** ⭐ | ZJT独有 |
| **宫格合并** | Prompt中描述 | **支持2x2/3x3** ⭐ | ZJT完整 |
| **并发控制** | ❌ 无 | **槽位机制（max=3）** ⭐ | ZJT完整 |
| **状态轮询** | ❌ 无 | **APScheduler+轮询（30s间隔）** ⭐ | ZJT完整 |
| **任务队列** | ❌ 无 | **Tasks表+状态机（0队列/1处理/2完成/-1失败）** ⭐ | ZJT完整 |
| **时长映射** | 固定15s/镜 | **std=5s/pro=10s等动态映射** ⭐ | ZJT更灵活 |

### 环节 7：音频制作

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **Lip-sync** | **唇形同步标注+[Lip-sync]标签** ⭐ | ❌ 无 | **漫舟独有** |
| **BGM处理** | 合并进Audio Layer注入VideoPrompt ⭐ | 独立background_music字段 | ZJT更独立 |
| **SFX处理** | 合并进Audio Layer注入VideoPrompt ⭐ | 独立字段 | ZJT更独立 |
| **情感控制** | 情绪曲线标注 | **4种方法（0=音色/1=情感参考/2=向量/3=文本）** ⭐ | ZJT更精细 |
| **TTS生成** | manzhou-tts-voice规范（待实现） | duomi_client/RunningHub API ⭐ | ZJT已实现 |
| **情感参考音频** | 待实现 | **emo_ref_path支持** ⭐ | ZJT已实现 |

### 环节 8：剪映导出

| 子项 | 漫舟 | ZJT | 差距 |
|------|------|------|------|
| **实现状态** | manzhou-export.md规范文档 | JianyingMultiTrackLibrary.py **已实现** ⭐ | ZJT大幅领先 |
| **时间单位** | 秒 | **微秒（int，微秒级精确）** ⭐ | ZJT更精确 |
| **轨道结构** | 单一轨（规范中） | **多轨（视频轨+音频轨分离）** ⭐ | ZJT完整 |

| **媒体文件** | 不复制（规范中） | **自动复制到Resources/local** ⭐ | ZJT完整 |
| **草稿版本** | 规范定义 | **360000版号+110.0.0版本** ⭐ | ZJT已实现 |

## 四、ZJT独有、漫舟缺失的关键流程节点

| # | ZJT独有流程 | 说明 | 借鉴价值 |
|---|------------|------|---------|
| 1 | **180度轴线+多人对话拆分** | 每角色强制独立镜头，避免全景对话导致的面部生成问题 | ⭐⭐⭐⭐⭐ |
| 2 | **【【】】标记→API→参考图** | 前端自动解析标记→查库→注入Prompt，角色一致性自动化 | ⭐⭐⭐⭐⭐ |
| 3 | **location_db_id/props_db_id校验** | 强制校验道具/场景ID存在性，禁止幻觉 | ⭐⭐⭐⭐ |
| 4 | **分镜组贪心重组算法** | 同场景连续镜头自动合并，节省成本 | ⭐⭐⭐ |
| 5 | **JSON三层截断修复** | LLM输出被截断时自动修复，保证健壮性 | ⭐⭐⭐⭐⭐ |
| 6 | **9种日志文件系统** | 每步操作完整记录，便于调试和复盘 | ⭐⭐⭐ |
| 7 | **三种图片模式** | 首尾帧/多参考/混合，适配不同视频模型 | ⭐⭐⭐⭐ |
| 8 | **槽位并发控制** | RunningHub最多3个并发任务，避免资源耗尽 | ⭐⭐⭐ |
| 9 | **APScheduler任务轮询** | 定时检查任务状态，不用前端主动轮询 | ⭐⭐⭐ |
| 10 | **ffprobe时长检测** | 导出时自动检测视频实际时长（微秒级） | ⭐⭐⭐ |
| 11 | **强制中景对话规则** | 对话镜头禁止使用全景/远景，保证面部质量 | ⭐⭐⭐ |
| 12 | **场景树形结构** | parent_id自引用，支持室内外/上下级场景嵌套 | ⭐⭐⭐ |

## 五、漫舟独有、ZJT缺失的关键流程节点

| # | 漫舟独有流程 | 说明 | 差异化价值 |
|---|------------|------|----------|

## 七、总结

| 维度 | 漫舟流程优势 | ZJT流程优势 |
|------|------------|------------|
| **自动化** | 线性流水线，强制顺序，减少人工干预 | 画布自由拖拽，灵活但依赖人工编排 |
| **角色一致性** | DNA 6层锚点更精细 | 【【】】+严禁外貌规则更强制 |
| **分镜质量** | 九宫格+双Prompt分离 | 180轴线+对话拆分+时长重组 |
| **工程化** | Skill文档，依赖人工执行 | 代码引擎，SSE实时反馈 |
| **视频质量** | --cref参考图引用 | 7种驱动+3种图片模式 |
| **音频** | Lip-sync唇形同步独有 | 情感控制4种方法更精细 |
| **进化** | 效果追踪+Prompt进化飞轮 | ❌ 完全缺失 |
| **导出** | 规范文档完整 | JianyingMultiTrackLibrary已实现 |
| **调试** | 无日志 | 9种日志文件完整 |

**核心结论**：漫舟的流程设计更**面向AI协作**（线性Pipeline+人类决策点），ZJT更**面向生产执行**（图谱+实时反馈+数据库）。两者最值得互鉴的是——漫舟借鉴ZJT的**180轴线规则**和**JSON截断修复**，ZJT借鉴漫舟的**Lip-sync标注**和**进化飞轮**。
