## 六、节点间数据流

```
故事脚本生成（剧本）
      ↓ @引用素材
角色三视图（角色图 × 3）
      ↓ @引用素材
首帧图生视频（角色图 → 视频）
      ↓
视频成片

故事脚本生成（剧本）
      ↓ @引用素材
音频生视频（音频 → 视频）
      ↓
视频成片
```

**核心机制**：`@引用素材` — 节点间通过引用机制传递数据，上游输出作为下游输入

## 八、与漫舟系统的关键差异

| 维度 | LibTV Canvas | 漫舟 AI Drama Studio |
|------|-------------|---------------------|
| **节点编排** | 可视化画布+节点+连线 | Skill串行编排 |
| **节点间数据传递** | `@引用素材`（引用上游输出）| 手动复制粘贴 |
| **画幅设置** | 每节点独立设置（比例/分辨率）| Prompt内指定 |
| **摄像机控制** | 6维度（缩放/倾斜/平移/旋转/对焦）| Prompt描述 |
| **镜头时长** | 节点级别设置（3/5/10秒）| Prompt内描述 |
| **声音克隆** | 内置功能（声音克隆模式）| 未覆盖 |
| **自动剪辑** | 无（节点手动拼接）| manzhou-audio 三轨整合 |
| **配音/BGM/SFX** | 未覆盖（音频生视频=音效+画面）| 完整覆盖 |

## 九、对漫舟的借鉴价值

### 9.1 可直接复用的设计

1. **画幅参数内化**：LibTV 在节点级别设置比例/分辨率，漫舟应从 Prompt 内提取为独立字段
2. **摄像机控制**：6维度参数（缩放/倾斜/平移/旋转/对焦）可补充到 manzhou-storyboard
3. **节点引用机制**：`@引用素材` = 漫舟的"引用上游Skill输出"理念，应明文定义接口契约

### 9.2 漫舟独有的优势

| 漫舟独有 | 说明 |
|---------|------|
| VO配音（`voice:`标签）| LibTV Canvas 无配音节点 |
| BGM情绪曲线（`[BGM:]`）| LibTV Canvas 无BGM节点 |
| SFX六维音效（`[SFX:]`）| LibTV Canvas 无音效节点 |
| 爆款算法（SRL/3-15-30）| LibTV Canvas 无此模块 |
| 风控审核（manzhou-safety）| LibTV Canvas 无此模块 |
