## 二、缺失的关键信息（无法绕过的）

### 🔴 P0 - 阻断级缺失

#### 2.1 POST API端点（最关键）

**现状**：只知道 GET `/api/canvas/v1/asset-reviews` 返回已有结果
**缺失**：不知道触发分镜生成的 POST 请求格式

```
需要知道：
- 端点URL是什么？（POST /api/canvas/v1/asset-reviews 还是其他？）
- 请求体是什么？（视频URL？视频文件？canvas ID？）
- 认证方式？（Bearer Token？如何获取？）
- 响应格式？（轮询？WebSocket？SSE？）
```

**实测发现**：
- Canvas API: `GET /api/conversation/v1/canvases/{canvas_id}` ✅
- Table API: `GET /api/conversation/v1/table-data/{table_id}` ✅
- Asset Reviews API: `GET /api/canvas/v1/asset-reviews` (只有GET，没有POST) ❌

#### 2.2 AI分析Prompt（核心）

**现状**：5步分镜Prompt（multi_angle_grid等）≠ 实际拉片分析Prompt
**缺失**：实际用于分析视频帧的Prompt模板

```
推测的缺失Prompt应包含：
- 视频帧输入格式（单帧/多帧？如何标注时间戳？）
- 镜头边界检测逻辑（如何判断镜头切换？）
- 分镜描述格式（中文分镜描述的标准是什么？）
- 角色识别（如何从帧中识别角色？）
```

#### 2.3 帧提取API

**现状**：知道帧存储位置，不知道提取过程
**缺失**：
```
- 提取工具？（WebAV / FFmpeg / 其他？）
- 提取策略？（固定间隔？关键帧检测？）
- 上传流程？（帧如何上传到 files.tapnow.ai？）
```

│                                                             │

### 4.2 最小可落地实现

```python
# 最简化版本（不需要逆向API）
class SimpleLapianAgent:
    def run(self, video_path: str) -> list[dict]:
        # 1. FFmpeg提取帧（每5秒1帧）
        frames = extract_frames(video_path, interval=5)

        # 2. 上传到OSS
        frame_urls = upload_to_oss(frames)

        # 3. 调用LLM分析（需要自行设计Prompt）
        prompt = self.build_analysis_prompt(frames, frame_urls)

        # 4. LLM返回分镜表（需要自行设计输出格式）
        shot_table = llm.analyze(prompt)

        return shot_table
```

### 4.3 自研Prompt框架（最小可行版）

```markdown
## 分镜分析Prompt（基于实测Schema逆向推导）

**输入**：视频关键帧图片列表（含时间戳）

**任务**：为每个镜头生成以下信息

**输出格式**：
镜号 | 开始时间 | 时长 | 景别 | 相机角度 | 运镜方式 |
光影 | 景深 | 分镜描述 | 画面描述 | 台词 | 音效 | 关键帧图

**镜头识别规则**：
- 景别判断：主体占画面比例
- 角度判断：相机与主体的高度关系
- 镜头切换：画面主体/场景明显变化时

**分镜描述规范**：
- 使用中文描述
- 描述主体动作和表情
- 不包含相机参数（相机参数单独标注）
- 台词用引号标注，无台词写"无"
- 音效用场景描述（如"环境音"、"背景音乐持续"）
```

## 五、结论

### 5.1 能否做出可落地的一键拉片Agent？

**答案：部分能，但核心能力无法复制**

| 能力 | 状态 | 说明 |
|------|------|------|
| 分镜Schema | ✅ 能做 | 14列完整字段，直接使用 |
| 镜头类型体系 | ✅ 能做 | 9景别+4角度+运镜，直接用 |
| UI渲染 | ✅ 能做 | 表格组件渲染分镜表 |
| **AI分镜分析** | ❌ 做不了 | Prompt和API均缺失 |
| **关键帧选取** | ❌ 做不了 | TapNow的AI选帧逻辑未知 |
| **完整体验** | ❌ 做不了 | 需完整逆向才能复制 |

### 5.2 核心缺失总结

```
┌──────────────────────────────────────────────────────────┐
│  缺失清单                                                  │
├──────────────────────────────────────────────────────────┤
│  1. POST /api/canvas/v1/asset-reviews 请求体格式            │
│  2. 视频帧提取策略（提取多少帧？按什么间隔？）              │
│  3. AI分镜分析Prompt（帧→分镜描述的Prompt）               │
│  4. 镜头边界检测逻辑（如何判断镜头切换？）                  │
│  5. 关键帧选取策略（从哪些帧生成关键帧图？）                │
│  6. 帧上传API（如何将帧上传到files.tapnow.ai？）           │
│  7. WebSocket/SSE响应机制（结果如何推送？）                │
└──────────────────────────────────────────────────────────┘
```

### 5.3 建议路径

**方案A（完全自研）**：放弃复制TapNow，从头构建分镜分析LLM Prompt
- 优势：不依赖TapNow，可完全自主
- 劣势：效果不确定，需大量测试
- 工作量：Medium（主要在Prompt调优）

**方案B（API逆向补全）**：继续逆向，找到POST端点和Prompt
- 优势：能复制TapNow体验
- 劣势：需要登录态抓包，或逆向JS bundle
- 工作量：High（可能遇到反爬/加密）

**方案C（混搭）**：使用TapNow的Schema + 自研LLM分析
- 优势：最快落地，有完整输出格式
- 劣势：AI分析效果取决于Prompt质量
- 工作量：Low-Medium
