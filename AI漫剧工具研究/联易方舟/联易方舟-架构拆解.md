# 联易方舟 - 底层架构拆解

> 研究日期：2026-03-24
> 研究方式：CDP抓包 + 页面分析 + 架构推理

---

## 一、核心发现：异步任务队列架构

### 1.1 发现的工作流API

```
请求流程：
1. POST 创建任务 → 返回 workflowId
2. GET /api/workflow/status/{workflowId}  → 轮询任务状态
3. GET /api/scripts/state → 脚本状态
```

### 1.2 技术特征

| 特征 | 观察 |
|------|------|
| 任务ID | UUID格式（如 35117665-df0a-434f-93b8-217b41ea8a11） |
| 轮询间隔 | 约2-3秒 |
| 状态端点 | `/api/workflow/status/{id}` |
| 脚本状态 | `/api/scripts/state?userId=xxx&projectId=xxx` |

## 二、剧本创作模块 - 三步流程

### Step 1：元素+创意
```
输入：故事核心设定（几百字）
处理：前端表单收集
输出：创意描述文本
```

### Step 2：生成大纲 ⭐ 核心
```
输入：
  - 创意文本（用户的故事情节）
  - 集数设置（20-100集）
  - 模板提示词（"短剧大纲专用"）
  - 自定义补充信息（可选）

处理流程（推测）：
  1. 拼接Prompt = 模板 + 创意 + 集数 + 补充
  2. 发送到后端 /api/workflow/create
  3. 后端调用大模型API
  4. 返回异步任务ID
  5. 前端轮询 /api/workflow/status/{id}
  6. 任务完成，获取大纲结果

输出：
  - 故事梗概
  - 分集大纲（每集钩子/冲突/反转/结尾）
  - 人物小传
```

### Step 3：分集创作
```
输入：选中某集的大纲
处理：调用大模型生成详细剧本
输出：分集剧本（对白+动作+场景描述）
```

## 三、技术架构推测

### 3.1 前端架构
```
React + Next.js
状态管理：React Query（用于轮询）
UI组件：Radix UI /shadcn/ui
样式：Tailwind CSS
```

### 3.2 后端架构
```
API层：Next.js API Routes
任务队列：自定义 + Redis（推测）
AI网关：统一AI调用层
模型适配：适配多种模型
```

### 3.3 AI模型层
```
支持的模型（50+）：
- Gemini3 Pro
- GPT-5.1
- Claude 4.5
- DeepSeek
- 智谱
- 文心一言
- 千问、豆包、Kimi、Grok

调用方式：统一AI网关 + 模型适配器
```

## 六、架构亮点

### 6.1 异步解耦
```
用户点击 → 创建任务ID → 立即返回 → 前端轮询
           ↓
        后端处理（可能需要30秒）
           ↓
        完成 → 前端更新UI
```
**优势**：用户体验好，不阻塞

### 6.2 模板市场
```
用户选择模板 → 自动填充Prompt → 生成
```
**优势**：降低门槛，标准化输出

### 6.3 知识库一致性
```
RAG检索 → 注入到Prompt → 生成时参考
```
**优势**：长篇创作保持设定一致
