## 七、完整Prompt模板体系

### 7.1 CDP改编脚本（4个模板）

#### 模板1: AI 漫剧-一键改编（CDP）官方模板
**ID**: `cmn3czllj04oev377an8std3u`
**用途**: 标准15S版，支持增量追加
**参数**: temperature=0.7, maxTokens=50000, topP=0.9

```
你正在为"短视频漫剧"做脚本改编（CDP）。请严格遵守：

【语言与合规】
1) 除非字段本身必须英文（如 gender 枚举），其余字段以中文为主输出；
   其中 videoPrompt 的 Shot/Duration/Scene 标题行可用英文（Scene 描述可中文）。
2) 禁止输出任何品牌/商标/具体 IP 名称。
3) 禁止输出"参考作品/致敬某某"的句式；reference 字段请输出空字符串或非常抽象的风格描述。

【结构化与可执行】
1) 每个 shot 对应一个"片段（segment）"，durationSec 为片段时长（秒），
   必须匹配视频模型可用时长档位（如 10/15/25）。
2) 镜头要有明确目标（objective），节奏紧凑：开场抓人→冲突升级→结尾钩子。
3) 角色/场景/道具要可复用：人物外观与服装描述稳定一致；场景描述具象可画。
4) videoPrompt 必须按 Sora2 标准分镜格式输出：
   先写一行 Global Context（含 no text/no subtitles/no music），
   再写 Shot N / Duration: X sec / Scene: ...；
   各 Shot Duration 之和应等于该片段 durationSec（允许 ±1 秒）。

【节奏与镜头数】
1) 每章/每集片段数要稳定可控：按"每集时长（分钟）/片段时长（秒）"规划片段数量。
2) 台词长度必须匹配片段时长：一个片段说不完必须拆分为多个 shot。
3) 识别人物别名并统一：同一角色的不同称呼/外号要归并为一个角色。

【增量追加（按章节/批次）】
```

## 十、核心发现与架构总结

### 10.1 CDP是唯一真实数据源

整个V3漫剧工作台的所有步骤都在操作同一份CDP JSON：

```
Step 1 全局设置  → settings写入 cdp.settings
Step 2 故事脚本  → CDP生成写入 cdpData.payload.cdp（字符/场景/物品/镜头）
Step 3 资产生成  → characterData/locationData/itemData.payload 存储生成结果
Step 4 分镜脚本  → 编辑 cdp.shots[] 中的 script/dialogue/imagePrompt/videoPrompt
Step 5 分镜视频  → videoJobs 存储视频生成任务状态
Step 6 视频预览  → 读取 cdp.shots[] + videoJobs 合成最终输出
```

### 10.2 增量追加机制

CDP通过 `existingCharactersJson/existingLocationsJson/existingItemsJson` 实现多章节追加：
- 同名角色/场景/物品复用已有id
- shotNumber 可从1开始，系统自动偏移
- 通过 `meta.append=true` 标记增量模式

### 10.3 videoPrompt Sora2格式

```
Global Context（无文字/无字幕/无音乐）
Shot 1 / Duration: X sec / Scene: [描述]
Shot 2 / Duration: X sec / Scene: [描述]
...
各Shot Duration之和 ≈ 该片段 durationSec（±1秒容差）
```

### 10.4 成本优化建议

**图片**: 优先使用 `channelA:sora-image`（¥0.02/张）做资产预览
**视频**: 优先使用 `sora-2-all`（¥0.14/15秒），性价比最高
**角色卡**: Gemini 3.1 Flash（¥0.10）足够清晰度需求
**分镜图**: Nano Banana（¥0.02-0.07）完全满足九宫格需求
