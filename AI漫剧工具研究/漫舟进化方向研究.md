# 漫舟进化方向研究
> 研究时间：2026-03-25
> 研究范围：联易方舟/智剧通/LibTV/TapNow/蝉妈妈/飞瓜

---

## 头部系统做法分析

### 1. 资产复用

#### 联易方舟 — CDP JSON Schema + ID引用体系
**核心机制**：CDP（Comic Drama Package）是整个系统的唯一真实数据源，通过ID引用实现跨集复用：
- **角色系统**：`id`（唯一标识）、`aliases[]`（别名数组）、外貌/服饰/人设完整档案
- **场景系统**：`id`引用 + `props[]`（道具列表）
- **道具系统**：30项道具分级（关键道具含appearance/description，普通道具仅id/name）
- **增量追加机制**：`meta.append=true` + `existingCharactersJson/existingLocationsJson/existingItemsJson`，支持多章节复用已有ID

**关键设计**：
```json
"shots": [{
  "locationId": "l_l1",      // ID引用而非文本
  "characterIds": ["c_c1"],  // 数组支持多角色
  "itemIds": ["i_i1"]        // 道具ID引用
}]
```

#### 智剧通(ZJT) — 数据库模型层
**核心机制**：完整MySQL模型层 + 树形结构：
- **World模型**：统一管理世界/故事大纲/视觉风格/色彩语言/构图偏好
- **Character模型**：`reference_image`（URL）+ `emotion_voices`（JSON情感音色）+ `sora_character`（外部ID）
- **Location模型**：`parent_id`自引用实现树形场景结构
- **Props模型**：道具参考图 + 描述独立存储
- **create_or_update()**：使用`INSERT ... ON DUPLICATE KEY UPDATE`解决并发问题

#### LibTV — 工作流复用机制
**核心机制**：节点串联可打包为模板，添加到工具箱：
- **角色三视图**：2x2网格（正面/侧面/背面/面部特写）
- **工作流模板**：一次调试，长期复利
- **双入口设计**：人和Agent均可调用同一工作流

#### TapNow — Visual Anchors锚点系统
**核心机制**：锁定跨帧必须保持的视觉特征：
```javascript
// Visual Anchors示例
visualAnchors: [
  "color tone", "key props", "light direction",
  "environmental markers", "character identity"
]
```
**资产库属性**：11类标签分类（时代/文化区域/题材/场景/性别/年龄段/物种/体格/身高/肤色/发色/气质）

**关键洞察**：
1. **ID引用体系是资产复用的核心**：从"文本名称"→"ID引用"，避免名称不一致导致的资产分裂
2. **增量追加机制是多集制作的关键**：第02集复用第01集的角色/场景/道具资产
3. **Visual Anchors是跨镜头一致性的保障**：明确哪些特征必须保持，哪些可以变化

### 2. 效果闭环

#### 漫舟 manzhou-hit-engine — 爆款算法引擎（国内最完整的爆款分析系统）
**SRL（压力-释放）模型**：
```
压力积攒（Pressure） → 临界点（Threshold） → 瞬间释放（Release） → 真空期（Vacuum）
```

**3-15-30规则**：
- 前3秒必须制造Hook（视觉奇观/身份错位/悬念台词）
- 每15秒必须引入新变量（Pulse）
- 每30秒必须完成一次小高潮（Climax）

**爆点触发矩阵**（4类核心触发器）：
| 触发器 | 剧本指令 | 视觉表现 | 音效配合 |
|--------|---------|---------|---------|
| 降维打击 | 反派嚣张→主角隐忍 | 俯拍主角+特写反派→眼神冷光一闪 | 心跳声渐强→突然安静 |
| 身份反转 | 道具亮出→全场震惊 | 慢动作特写+金色流光 | 瞬间静音→低音重鼓点 |
| 断点悬念 | 动作90%切断 | 刀刃贴近→切黑屏 | 音效骤停 |
| 情绪反转 | 高潮→戛然而止→相反情绪 | 对峙中突然安静 | 激烈切静音 |

**爽/虐节奏映射**：
- 爽剧：前轻后重，第2/4/6/8/10/12集为爆点密集集（集均8-12个爆点）
- 虐剧：前密后疏，最后一集爆发式虐点

#### TapNow — 分镜表数据结构
**14列标准Schema**：
```
镜号 | 时长 | 时间轴位置 | 景别 | 相机角度 | 运镜 | 场景标签 | 分镜描述 | Visual Prompt | Keyframes
```

#### 蝉妈妈/飞瓜数据（无本地资料）
本地研究资料中未找到蝉妈妈、飞瓜数据的AI漫剧分析系统资料。根据公开信息：
- **蝉妈妈**：抖音电商数据分析平台，提供短视频/直播带货数据
- **飞瓜数据**：类似平台，专注抖音/快手数据追踪
- **能力推测**：播放量/完播率/点赞/评论/转化率等指标追踪，但未涉及AI漫剧内容质量分析

**关键洞察**：
1. **漫舟的爆款引擎是竞品中最完整的**：国内唯一将SRL模型量化的系统
2. **效果闭环需要数据追踪能力**：目前缺"发布后数据→Prompt迭代"的完整闭环
3. **爆款因子可结构化为规则引擎**：3-15-30规则比主观判断更可靠

### 3. 系统进化

#### TapNow — Prompt模板5步分镜法
**可复用的Prompt Learning结构**：
```
Step 1: Scene Breakdown → Subjects + Environment + Lighting + Visual Anchors
Step 2: Theme → 单句描述情绪/主题
Step 3: Cinematic Approach → 9帧策略（ELS/LS/MLS/MS/MSCU/CU/ECU/高角/低角）
Step 4: Keyframes → 9个KF的Composition/Perspective/Camera/Lens/Grade
Step 5: Contact Sheet → 输出一张3x3分镜图
```

#### TapNow — Hollywood光影知识库
**Roger Deakins级Prompt约束**：
- 动机光源规则（Diegetic Only）：每盏灯必须来自场景内逻辑光源
- 短光规则（Short Lighting）：主光应照亮背对相机的面部
- 反平方定律：前景亮→中景→背景的衰减必须符合物理规律
- 色温逻辑：火/烛光1800-3200K，日光/月光5600-8000K

#### 联易方舟 — Prompt模板体系（74个模板）
**可量化学习的模板分类**：
| 类别 | 数量 | 核心价值 |
|------|------|---------|
| 续写工具 | 23 | 章节衔接逻辑 |
| 润色工具 | 19 | 去AI味/文采提升 |
| 大纲/卷纲 | 13 | 多级结构规划 |
| 细纲工具 | 11 | 章节规划细化 |

#### LibTV — 工作流可复用机制
- 将节点串联打包为工作流模板
- 添加到工具箱，长期复用
- Agent可调用同一工作流

#### AI视频生成反馈循环（无本地竞品资料）
公开领域的AI视频Prompt Learning机制：
- **Midjourney风格**：用户投票/评分 → Top Prompt模式提取 → 高频词汇权重提升
- **系统级学习**：播放完成率 → Prompt关键词强化 → 弱化无人看词汇
- **A/B测试闭环**：同镜头多Prompt变体 → 数据对比 → 优选Prompt固化

**关键洞察**：
1. **Prompt Learning = 模板 + 约束 + 反馈**：TapNow的5步法是可学习的结构
2. **知识库是系统进化的载体**：Hollywood光影知识库可注入漫舟视觉风格
3. **反馈闭环需要数据基础设施**：播放数据→Prompt迭代需要埋点和追踪

## 对漫舟的启发

### 核心建议

#### 建议1：建立资产复用ID体系（P0优先级）
```
现状：角色/场景/道具以文本形式分散在多个Skill输出中
目标：建立统一CDP JSON Schema，实现ID引用机制
行动：
1. 采用联易方舟CDP JSON Schema作为漫舟资产包标准格式
2. 在manzhou-script.md中输出characters/locations/items的ID映射
3. 后续Skill引用ID而非文本
4. 实现meta.append=true的增量追加机制
价值：支持多集制作，资产不重复生成
```

#### 建议2：构建爆款数据追踪闭环（P1优先级）
```
现状：manzhou-hit-engine已完成爆款检测，但无发布后数据追踪
目标：建立"生成→发布→数据→迭代"的完整反馈闭环
行动：
1. 记录每集生成的Prompt版本（image_prompt/video_prompt）
2. 接入平台数据API（抖音/快手）获取播放/完播/转化数据
3. 建立Prompt效果评分：爆款Prompt → 权重提升
4. 新项目自动推荐历史高绩效Prompt
价值：从"规则驱动"升级为"数据驱动"
```

#### 建议3：构建Prompt知识库体系（P2优先级）
```
现状：Prompt以Markdown文件分散，缺乏版本管理和可发现性
目标：建立可积累、可检索、可复用的Prompt知识库
行动：
1. 参考TapNow的5步分镜法，重构manzhou-storyboard.md
2. 注入Hollywood 5灯知识库到manzhou-visual-style.md
3. 建立景别体系标准：9种标准景别（ELS→ECU）
4. 实现"失败Prompt追踪"：记录生成失败/低质量Prompt及原因
价值：系统越用越聪明，Prompt持续进化
```
