# Saleor 平台分析

> **版本**: 3.24.0 (alpha) | **许可证**: BSD-3-Clause | **官方**: [saleor.io](https://saleor.io) | **GitHub**: [saleor/saleor](https://github.com/saleor/saleor)

---

## 平台概述

Saleor 是一款**模块化、高性能、headless 电商平台**，以 Python + GraphQL + Django 为核心构建，主打 API-first 设计理念。与传统 WordPress/Magento 的单体插件架构不同，Saleor 采用**服务化扩展机制**，所有功能均通过 GraphQL API 访问，不存在插件直接侵入核心代码路径的问题。

**核心定位**：面向需要**日更部署、高可用、多团队协作**的中大型电商场景。

---

## 技术栈

| 层次 | 技术选型 |
|------|---------|
| **语言** | Python 3.12（严格约束 `>=3.12,<3.13`） |
| **Web 框架** | Django 5.2.11 + Uvicorn ASGI |
| **API 层** | GraphQL（Graphene + graphql-core） |
| **数据库** | PostgreSQL（psycopg3） |
| **缓存** | Redis（dj-cache-url / django-redis） |
| **任务队列** | Celery + Celery Beat（含 DatabaseScheduler） |
| **消息中间件** | Redis / AWS SQS / CloudAMQP |
| **存储** | AWS S3 / Google Cloud Storage / Azure Blob |
| **前端** | React + TypeScript + Next.js（Storefront / Dashboard 独立仓库） |
| **监控** | OpenTelemetry（API + SDK + OTLP 导出） |
| **代码质量** | Ruff + MyPy + Pydantic + pytest |

> [!note]
> 数据库目前**仅支持 PostgreSQL**，不支持 MySQL 或 SQLite（生产级要求）。

### API-only + Headless 扩展模型

Saleor 的扩展通过以下机制实现，**完全不依赖插件注入核心代码**：

| 扩展方式 | 说明 |
|---------|------|
| **Apps** | 安装独立部署的 App，通过 Webhook / 同步事件 / Dashboard iframe 扩展功能 |
| **Webhooks** | 事件驱动 HTTP POST，支持订阅查询（Subscription Webhooks） |
| **Attributes & Metadata** | 在所有核心模型上附加键值元数据，无需改 schema |
| **Dashboard Iframes** | App 可在 Dashboard 中嵌入任意 Web 技术的 UI |
| **API Extensions** | 同步事件（Synchronous Webhooks）允许 App 拦截并修改 API 响应 |

### 并发与线程安全规范

Saleor 在多个 Python 进程中并发执行，有严格的并发编程规范：

```python
# 原子递增 — 使用 F() 表达式
Model.objects.filter(pk=pk).update(count=F("count") + 1)

# 复杂读写 — 使用 select_for_update 行锁
with traced_atomic_transaction():
    obj = Model.objects.select_for_update().get(pk=pk)

# upsert — 使用 update_or_create（需唯一约束）
obj, created = Model.objects.update_or_create(app=app, key=key, defaults={...})
```

## 核心模块详解

### Checkout（购物车与结账）

```
checkout/
├── models.py          # Checkout / CheckoutLine 模型
├── calculations.py     # 价格与税额计算
├── complete_checkout.py # 结账完成流程
├── checkout_cleaner.py  # 结账前置校验
├── fetch.py            # 数据加载器
├── payment_utils.py    # 支付关联工具
├── webhooks/           # 结账事件 Webhook
└── tasks.py            # Celery 异步任务
```

### Order（订单）

支持复杂订单模型：拆单、多仓库发货、退货退款、分期付款。与 Checkout 共享计算逻辑层。

### Payment（支付）

```
payment/gateways/
├── stripe/             # Stripe Gateway
├── braintree/          # Braintree Gateway
├── razorpay/           # Razorpay Gateway
├── authorize_net/      # Authorize.Net Gateway
├── dummy/              # 测试用 Dummy Gateway
└── dummy_credit_card/  # 测试信用卡 Gateway
```

支持**Payment App 机制**：支付由独立 App 处理，核心平台仅做事务记录（Transaction Item Model）。

### Discount（促销引擎）

支持三种促销机制：
- **Sales**：直接折扣（按商品/类目）
- **Vouchers**：优惠券（代码 + 适用范围）
- **Cart Rules**：购物车规则（满减、包邮等条件规则）

### Plugins（插件系统）

内置插件：
- `admin_email` — 管理员邮件通知
- `user_email` — 用户邮件通知
- `avatax` — Avalara 税务计算
- `openid_connect` — SSO 登录
- `sendgrid` — SendGrid 邮件发送
- `webhook` — 通用 Webhook

### Webhook 事件系统

完整的异步事件体系，支持：
- `order.created / order.updated / order.canceled`
- `checkout.created / checkout.updated`
- `payment.authorized / payment.captured`
- `product.created / product.updated`
- 自定义订阅查询（Subscription Webhook Payloads）

## GraphQL API 特性

Saleor 是**纯 GraphQL 平台**（无 REST API），API 设计规范：

- **Schema 版本管理**：每个字段标注 `ADDED_IN_{VERSION}`，按版本演进
- **权限控制**：使用 `PermissionsField` 描述字段级权限
- **查询成本控制**：`query_cost_map.py` 防止滥用
- **N+1 解决**：DataLoader 模式遍布全栈
- **实时订阅**：GraphQL Subscriptions（通过 WebSocket）

**管理操作**：
- 产品目录管理（全属性、变体、类型）
- 多渠道价格/库存独立控制
- 促销规则配置
- 订单全生命周期管理
- 支付与退款
- 礼品卡
- CMS 页面与菜单

## 优缺点分析

### 优点

> [!success]+ 优势

- **API-first 设计**：完全 headless，前端技术栈完全自由
- **GraphQL 原生**：类型安全、查询灵活、无 REST over-engineering
- **多渠道内置**：Channel 机制原生支持 B2B/B2C 多站点
- **促销引擎成熟**：Sales / Vouchers / Cart Rules 三层覆盖常见场景
- **多仓库库存**：Warehouse 模块支持复杂库存分配逻辑
- **支付抽象完整**：Transaction Item Model 支持 Payment App 模式
- **OpenTelemetry 集成**：开箱即用的可观测性
- **Celery 异步任务**：Webhook、邮件、缩略图等全部异步化
- **活跃社区**：Discord + GitHub，Roadmap 公开，Good First Issue 友好
- **开源无锁定**：BSD-3-Clause，单一代码库，无商业版功能分裂

### 缺点

> [!warning]+ 局限

- **Python 3.12 强制**：生态兼容性受限，不支持 PyPy
- **数据库单一**：仅支持 PostgreSQL，部署复杂度高
- **学习曲线陡**：GraphQL + Django + Celery + Webhook 全家桶门槛高
- **前端非内置**：Dashboard 和 Storefront 为独立仓库，需额外集成
- **中文社区弱**：文档和社区以英文为主，中文资源匮乏
- **无内置 CDN/媒体处理**：需自行对接 Cloudflare/R2 + 图像 CDN

## 适用场景

| 场景 | 推荐度 | 说明 |
|------|--------|------|
| **多站点 B2B/B2C** | 5/5 | Channel 机制原生支持多渠道 |
| **高频部署的微服务电商** | 5/5 | App 独立部署，升级无冲突 |
| **移动 App + Web 双前端** | 5/5 | 纯 GraphQL API，前端完全解耦 |
| **大促高并发电商** | 4/5 | Celery + Redis + SQS，扩展性强 |
| **中小型独立站（预算有限）** | 3/5 | 运维复杂度高，需要 DevOps 能力 |
| **快速 MVP 电商** | 2/5 | 起步成本高，不如 Shopify / Medusa 快捷 |
| **需要 MySQL 兼容的项目** | 1/5 | 仅 PostgreSQL，不可接受 |

## 快速上手

### 本地开发

```bash
# 克隆平台全家桶
git clone https://github.com/saleor/saleor-platform
cd saleor-platform

# Docker Compose 启动
docker compose up

# 或手动安装
cd saleor
pip install -e ".[dev]"
poe populatedb   # 填充测试数据（admin@example.com / admin）
poe start         # 启动开发服务器
poe worker        # 启动 Celery Worker
poe scheduler      # 启动 Celery Beat
```

### Cloud 快速体验

```bash
npm i -g @saleor/cli
saleor register           # 注册 Saleor Cloud 账号
saleor storefront create  # 一键拉起 storefront
```

### 关键开发命令（poe tasks）

| 命令 | 说明 |
|------|------|
| `poe start` | 热重载开发服务器 |
| `poe worker` | Celery Worker |
| `poe scheduler` | Celery Beat 调度器 |
| `poe migrate` | 执行数据库迁移 |
| `poe populatedb` | 填充测试数据 |
| `poe build-schema` | 导出 GraphQL Schema 到文件 |
| `poe test` | 运行测试（带 db reuse） |
