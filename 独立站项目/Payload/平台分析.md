# Payload CMS 平台分析

> [!abstract]
> Payload CMS 是全球首个 Next.js 原生 CMS（v3.80.0），采用 monorepo 架构，支持直接安装在 `/app` 目录中。它既是应用框架，又是无头 CMS，100% 开源，100% TypeScript，内置 GraphQL/REST API、Auth、Versioning、Localization 等功能。

---

## 1. 平台概述

Payload 重新定义了 Headless CMS 的边界：它不是独立托管的 SaaS 产品，而是可以直接嵌入 Next.js 项目 `/app` 目录中的 TypeScript 包。

### 核心定位

| 维度 | Payload | 传统 Headless CMS (Strapi/Contentful) |
|------|---------|--------------------------------------|
| 部署方式 | 嵌入项目，可 serverless | 独立服务 |
| 供应商锁定 | 无，完全自托管 | 受制于 SaaS 平台 |
| 前端框架 | 原生 Next.js / RSC | API 驱动，无限制 |
| 数据库 | 自选（Postgres/MongoDB/SQLite...） | 平台托管 |
| 成本 | 免费开源，服务器成本 | 按量/按订阅收费 |

### 核心特性清单

- 100% 开源（MIT）
- Next.js 原生，可安装进 `/app` 文件夹
- React Server Components 直接查询数据库
- 100% TypeScript，类型自动生成
- 内置 **Authentication**（支持 OAuth、API Key、JWT）
- **版本管理 & 草稿**（draft/publish 生命周期）
- **国际化 / Localization**
- **Block-based Layout Builder**
- **Lexical 富文本编辑器**（替代 Slate）
- **粒度级 Access Control**
- **Document & Field Hooks**
- REST API + GraphQL API 双输出
- HTTP-only cookies + CSRF 保护

## 2. 技术栈

### 语言与运行时

| 项目 | 版本 |
|------|------|

- **AI 集成**: `ai 6.0.95` + `@ai-sdk/openai 3.0.30`
- **构建**: Turbo (`turbo 2.5.4`) + SWC
- **测试**: Vitest + Playwright
- **验证**: Zod `4.3.6`

## 3. 架构

### 3.1 Monorepo 结构

```
payload-monorepo/
├── packages/          # 43 个可发布包
├── test/              # 按功能域组织的测试套件
├── docs/              # 部署到 payloadcms.com 的文档
├── tools/             # Monorepo 构建工具
├── templates/         # 生产级项目模板
│   ├── website/       # 完整官网模板（Tailwind + RSC）
│   └── ecommerce/     # 电商模板
└── examples/          # 示例实现
```

### 3.2 核心包（Core Packages）

| 包名 | 职责 |
|------|------|
| `packages/payload` | 核心 CMS 逻辑 |
| `packages/ui` | Admin UI 组件（React Server Components） |
| `packages/next` | Next.js 集成层 |
| `packages/graphql` | GraphQL API 层 |
| `packages/sdk` | 统一 SDK |
| `packages/admin-bar` | Admin Bar 组件 |
| `packages/translations` | i18n 翻译文件 |

### 3.3 数据库适配器（5 个）

> Drizzle ORM 作为底层抽象层，所有数据库适配器均基于 Drizzle 实现。

| 包 | 数据库 | 部署场景 |
|----|--------|---------|
| `@payloadcms/db-mongodb` | MongoDB | 传统 VPS / 内存开发 |

| `@payloadcms/db-sqlite` | SQLite | 轻量 / 本地开发 |

| `@payloadcms/db-vercel-postgres` | Vercel Postgres | Vercel 平台 |
| `@payloadcms/drizzle` | 通用 Drizzle 集成层 | 自定义 ORM 场景 |

## 4. 部署模式

### 4.1 Cloudflare（一键部署）

> [!tip]
> 完整自包含方案：Payload Workers + R2 存储 + D1 数据库，全球复制。

- 部署地址: [dub.sh/payload-cloudflare](https://dub.sh/payload-cloudflare)

### 4.2 Vercel（一键部署）

> [!tip]
> Next.js 全栈方案：Next.js 前端 + Neon PostgreSQL + Vercel Blob。

- 部署地址: [dub.sh/payload-vercel](https://dub.sh/payload-vercel)

### 4.3 传统 VPS / Docker

- 支持任何 Node.js 18+ 服务器
- Docker Compose 配置文件在 `test/docker-compose.yml`

## 5. 优缺点分析

### 优点

| 优点 | 说明 |
|------|------|
| 零供应商锁定 | 完全自托管，不依赖任何 SaaS |
| Next.js 原生 | 安装到 `/app`，RSC 直接查询数据库，无需 REST/GraphQL 中转 |
| TypeScript First | 配置即类型，类型自动推断，IDE 完整支持 |
| 架构简洁 | 单仓库管理前后端，减少认知负担 |
| 插件生态完整 | 15 个官方插件，覆盖电商/SEO/搜索/支付等场景 |
| 存储灵活 | 6 种云存储适配器 |
| 数据库灵活 | 支持 MongoDB、PostgreSQL、SQLite、D1、Vercel Postgres |
| 开源免费 | MIT 许可证，无使用成本 |

### 缺点

| 缺点 | 说明 |
|------|------|
| 供应商绑定（部署端） | 虽无 CMS SaaS 绑定，但部署在 Cloudflare/Vercel 上仍有平台依赖 |
| 学习曲线 | 相比 Strapi，概念更密集（Config as Code、Hooks、Access Control） |
| 文档质量波动 | 部分高级功能文档较简略 |
| 管理 UI 定制有限 | Admin UI 定制需要深入 React 知识 |
| Monorepo 体积大 | 3.80.0 版本包体积较大，首次构建耗时长 |
| 社区规模 | 相比 Strapi、Directus，社区较小 |

## 6. 适用场景

### 非常适合

- **Next.js 全栈项目**：直接嵌入 `/app`，前后端同一仓库
- **电商平台**：官方 `plugin-ecommerce` + `plugin-stripe`
- **内容型 SaaS**：白标+多租户插件支持
- **需要强类型 CMS**：TypeScript 项目中享受端到端类型安全
- **自托管需求**：不想用 Contentful/Strapi 的 SaaS 版本
- **Serverless 部署**：Vercel / Cloudflare Workers 免费层

### 不太适合

- 非 TypeScript / 非 Next.js 项目
- 需要拖拽可视化页面编辑器的用户（非 Block Builder）
- 需要超大规模（百万级文档）的场景（需评估数据库选型）

## 9. 项目规范摘要（CLAUDE.md）

> [!note]
> 以下为 Payload monorepo 开发规范，摘录自 `CLAUDE.md`。

### 开发环境

```bash
pnpm install                          # 安装依赖
pnpm run build:core                   # 构建核心包
pnpm run dev                          # 启动开发服务器（默认 MongoDB）
pnpm run dev:postgres                 # 使用 PostgreSQL 启动
pnpm docker:start                     # 启动 Docker 服务
```

### 测试

| 命令 | 范围 |
|------|------|
| `pnpm test` | 全部（集成 + 组件 + E2E） |
| `pnpm test:int` | 集成测试（MongoDB） |
| `pnpm test:int:postgres` | PostgreSQL 集成测试 |
| `pnpm test:e2e` | Playwright E2E 测试 |
| `pnpm test:e2e:headed` | 有头浏览器 E2E |

### 代码规范

- 单对象参数（优于多参数，便于向后兼容）
- `types` 优于 `interface`（扩展外部类型除外）
- 函数优于 Class（Class 仅用于错误/适配器）
- 布尔值前缀 `is`/`has`/`can`/`should`
- 日志使用 `payload.logger.error({ msg: '...', err: error })`

### Commit 规范（Conventional Commits）

```
<type>(<scope>): <title>
feat(db-mongodb): add support for transactions
fix(ui): json field type ignoring editorOptions
```

### AI 工具兼容性

| 工具 | Context | Skills | Hooks | MCP |
|------|---------|--------|-------|-----|
| Claude Code | 支持 | 支持 | 支持 | 支持 |
| Cursor | 支持 | 支持 | 支持 | 支持 |
| VS Code + Copilot | 警告 | 支持 | 不支持 | 支持 |
