## 平台概述

Medusa 是一个**开源的 Headless 电商平台**，提供模块化的商务构建块，允许开发者构建自定义电商应用，无需重复造轮子。

> [!abstract] 核心定位
> "Building blocks for digital commerce" — 不是完整的 SaaS，而是一套可自由组合的商务基础设施。

### 官方定位场景

- **DTC 品牌独立站**（Direct-to-Consumer）
- **B2B 批发平台**
- **多商户 Marketplace**
- **PoS 线下零售系统**
- **服务型业务**（预约、订阅）

## 核心模块详解

### 1. MedusaService 架构

所有模块服务均继承 `MedusaService<T>`，通过装饰器实现横切关注点：

```typescript
export class OrderModuleService
  extends MedusaService<{ Order: { dto: OrderDTO } }>({ Order })
  implements IOrderModuleService
{
  @InjectManager()       // 注入 EntityManager
  @EmitEvents()         // 方法执行后发送领域事件
  async deleteOrders(
    ids: string[],
    @MedusaContext() sharedContext: Context = {}
  ) {
    return await this.deleteOrders_(ids, sharedContext)
  }

  @InjectTransactionManager()  // 事务管理
  protected async deleteOrders_(...) {
    await this.orderService_.softDelete(ids, sharedContext)
  }
}
```

**核心装饰器**:

| 装饰器 | 用途 |
|--------|------|
| `@InjectManager()` | 注入数据库 EntityManager |
| `@InjectTransactionManager()` | 注入事务管理器 |
| `@MedusaContext()` | 注入共享上下文（用户信息/事务ID） |
| `@EmitEvents()` | 自动发送领域事件 |
| `@Db Lola/MikroORM` | DAL 层注解 |

### 2. Workflow 工作流编排

Medusa v2 的核心创新之一：**Saga + Step Function** 混合模式。

```typescript
// Step 定义（含补偿/回滚逻辑）
export const deletePromotionsStep = createStep(
  "delete-promotions",
  async (ids: string[], { container }) => {
    const promoModule = container.resolve<IPromotionModuleService>(Modules.PROMOTION)
    await promoModule.softDeletePromotions(ids)
    return new StepResponse(void 0, ids)  // 回滚数据放在第二个参数
  },
  async (idsToRestore, { container }) => {
    if (!idsToRestore?.length) return
    const promoModule = container.resolve<IPromotionModuleService>(Modules.PROMOTION)
    await promoModule.restorePromotions(idsToRestore)
  }
)

// Workflow 组合
export const deletePromotionsWorkflow = createWorkflow(
  "delete-promotions",
  (input: WorkflowData<{ ids: string[] }>) => {
    const deleted = deletePromotionsStep(input.ids)
    const hook = createHook("promotionsDeleted", { ids: input.ids })
    return new WorkflowResponse(deleted, { hooks: [hook] })
  }
)
```

**编排原语**:

- `createStep()` — 带补偿的业务步骤
- `createWorkflow()` — 组合工作流
- `transform()` — 数据转换
- `when()` — 条件执行
- `parallelize()` — 并行执行
- `createHook()` — 发出业务钩子

## 优缺点分析

### 优势

> [!success]+ 优势

- **[[Modular Architecture|模块化架构]]** — 30+ 独立模块可按需选用，替换任意实现
- **Headless 优先** — 完全前后端分离，API-first，支持任何前端框架
- **开箱即用的 Admin** — 功能完整的 React Dashboard，无需自建后台
- **Workflow 编排** — 内置 Saga 模式，含自动回滚补偿机制
- **TypeScript 原生** — 全链路类型安全，IDE 友好
- **丰富的 Provider 生态** — Stripe / S3 / SendGrid / Redis 等官方支持
- **活跃社区** — Discord 14,000+ 成员，持续更新
- **MIT 许可证** — 商业友好，无供应商锁定

### 劣势

> [!warning]+ 劣势

- **v2 相对不成熟** — v2（2.x）是重大重构，部分生态插件仍在适配
- **文档碎片化** — 模块化设计好但文档分散，学习曲线陡
- **官方插件有限** — 相比 Shopify App 生态，第三方集成数量少
- **自托管运维成本** — 需要自行管理服务器、数据库、CDN、监控
- **无内置搜索引擎** — Search 模块需额外集成（Elasticsearch/Meilisearch）
- **升级风险** — 2.x 大版本变化大，breaking changes 较多
