### 一键拉片功能（Shot Breakdown）⭐

**核心价值**：AI自动分析成品短剧视频，生成分镜脚本

#### 输入 / 输出

| | 内容 |
|------|------|
| **输入** | 成品短剧视频（MP4等） |
| **输出** | 14列结构化分镜表 |

#### 实测分镜Schema（14列）

| 字段 | 示例 |
|------|------|
| 镜号 | 1, 2, 3...32 |
| 开始时间(s) | 2.8, 4.2, 5.1... |
| 时长(s) | 2.8, 1.4, 0.9... |
| 分镜描述 | "一名身穿花衬衫的男子站在便利店内，伸手整理头发，神情略显困惑。" |
| 画面描述 | "顾客（男A）询问店主这里最畅销的水果。" |
| 台词 | "咱们这卖的最好的水果是什么呀" / "无" |
| 相机角度 | 平视镜头 / 俯拍镜头 / 仰拍镜头 / 过肩镜头 |
| 景别 | 近景 / 中近景 / 特写 / 中景 |
| 运镜方式 | 固定镜头 |
| 光影风格 | 三点布光 / 自然光 / 高调光 |
| 景深 | 浅景深 |
| 关键帧图URL | https://app.tapnow.ai/api/conversation/storage/uploads/{uuid} |
| 结束时间(s) | 0.0, 4.2, 5.1... |
| 音效 | 环境音 / 背景音乐持续 / 轻柔悬疑音乐起 |

**实测数据**：134秒视频 → 32个镜头 → 14个字段

#### 镜头类型体系（完整）

| 景别 | 描述 | 典型场景 |
|------|------|---------|
| 特写 ECU | 局部细节 | 草莓罐头、罐头顶部、手部动作 |
| 近景 CU | 肩部以上 | 顾客面部、沉思表情 |
| 中近景 MCU | 胸口以上 | 店主解释、顾客提问 |
| 中景 MS | 膝上/全身 | 过肩镜头、侧身站姿 |
| 中远景 MLS | 全身 | 场景交代 |
| 远景 LS | 环境镜头 | 便利店全貌 |
| 极远景 ELS | 交代镜头 | 城市/街道 |
| 高角俯拍 | 俯视 | 商品展示、草莓特写 |
| 低角仰拍 | 仰视 | 顾客向往、顾客纠结 |
| 过肩镜头 OS | 越过肩部 | 店主递纸巾场景 |

## Prompt体系（核心借鉴）

### 5步分镜Prompt（九宫格多机位）

```
Step 1 – Scene Breakdown: 主体/环境/视觉锚点
Step 2 – Theme: 一句话情绪主题
Step 3 – Cinematic Approach: 9帧策略/镜头/焦段/光色
Step 4 – Keyframes: 9个关键帧描述（景别/构图/机位/焦段）
Step 5 – Contact Sheet: 3×3拼图输出 + 文字描述
```

### Hollywood光影知识库（可复用逻辑）

```
1. 有据可查的光源（Diegetic Only）→ 不允许悬浮灯光
2. 短光规则（Short Lighting）→ 照亮背对相机侧
3. 平方反比定律 → 前景亮→中景→背景
4. 色温逻辑 → 火/烛光1800-3200K / 日光5600-8000K
5. PBR材质物理 → 皮肤SSS / 金属Fresnel
```

## 自建一键拉片Agent可行性

### 已有信息（可直接用）

- 分镜表Schema（14列完整）
- 镜头类型体系（9景别+4角度+运镜方式）
- 节点数据结构
- 定价模型

### 无法复制（P0阻断）

1. **POST API端点** — 触发分镜生成的请求体格式未知
2. **AI分析Prompt** — 帧→分镜描述的实际Prompt缺失
3. **帧提取策略** — 提取多少帧/按什么间隔未知
4. **镜头边界检测** — 如何判断镜头切换未知
5. **帧上传API** — 如何上传帧到files.tapnow.ai未知
6. **响应机制** — WebSocket/SSE推送未知

### 自建最小可行路径（方案C：混搭）

```
视频上传 → FFmpeg提取帧 → 上传到OSS → 自研LLM分析Prompt → 14列分镜表
```

**工作量**：Low-Medium（主要在Prompt调优）
