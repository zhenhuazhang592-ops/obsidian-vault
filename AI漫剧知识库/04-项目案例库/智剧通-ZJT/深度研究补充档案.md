### 1.3 三层配置体系

```
动态配置（数据库） > YAML配置文件 > 默认值
```

- 动态配置带30秒TTL缓存，支持后台热更新
- 前端通过 `/api/system/task-configs` 获取，无需硬编码

### 1.4 算力抽象层

两种计费模式：
```python

computing_power = 18

# 按时长计费
computing_power = {5: 38, 10: 70}  # 5秒=38算力，10秒=70算力
```

## 二、LLM剧本解析系统

### 2.1 parse_script_to_shots() 核心函数

```python
async def parse_script_to_shots(
    script_content: str,
    max_group_duration: int = 15,    # 分镜组时长上限
    world_id: Optional[int] = None,
    model: Optional[str] = None,
    force_medium_shot: bool = False, # 强制中景对话
    no_bg_music: bool = False,       # 禁用背景音乐
    split_multi_dialogue: bool = False,  # 多人对话拆分
    narration_as_dialogue: bool = False, # 旁白视为对话
) -> Dict[str, Any]
```

### 2.2 四大特殊参数（关键设计）

| 参数 | 规则 | 设计动机 |
|------|------|---------|
| `force_medium_shot` | 对话镜头禁止全景/远景，必须近景/中景开头 | Sora全景对话面部难以生成清晰 |
| `no_bg_music` | background_music 必须为null | 方便后期调音处理 |
| `split_multi_dialogue` | 多人对话必须拆分为单人镜头 | 视频生成质量+180度轴线规则 |
| `narration_as_dialogue` | 自动创建char_narrator角色 | 支持解说剧模式 |

### 2.3 【【】】角色标记系统（核心亮点）

**标记语法**：`【【角色名】】`

**系统处理流程**：
```
1. LLM生成JSON时，在角色名两侧添加【【】】标记
2. 后处理提取所有【【】】包裹的文本
3. 与角色库（CDP）匹配，获取reference_image
4. 生成参考图时确保角色一致性
```

**禁止使用场景**：场景名、地点名、物品名、道具名

### 2.4 180度轴线规则（多人对话拆分核心）

```
假设A和B对话，建立虚拟轴线连接两人
摄像机必须始终保持在轴线同一侧

正确：角色A在画面左侧面向右，角色B在画面右侧面向左（正反打）
错误：角色A和B都面向同一方向，或位置关系突然颠倒
```

### 2.5 数据库关联机制

```python
# LLM Prompt中注入已有资产
db_locations = LocationModel.get_tree_by_world(world_id=world_id, limit=20)
# → 告知LLM只能使用数据库中的location_db_id，禁止编造
```

### 7.4 相机描述生成

```javascript
function convertCameraToPrompt(camera) {
    // Yaw转换（0度为正面）
    if (camera.yaw <= -75) parts.push('正侧面轮廓视图，人物面朝右');
    else if (camera.yaw > -5 && camera.yaw < 5) parts.push('正面视图');

    // Dolly转换 - 景别
    if (camera.dolly >= 4 && camera.dolly < 6) parts.push('中景');
    else if (camera.dolly >= 8) parts.push('特写');

    // Pitch转换 - 拍摄角度
    if (camera.pitch <= -45) parts.push('极低角度仰视');
    else if (camera.pitch >= 45) parts.push('极高角度俯视');
}
```
