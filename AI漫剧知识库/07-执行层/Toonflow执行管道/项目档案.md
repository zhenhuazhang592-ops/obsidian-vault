## Agent体系（src/agents/）

### 1. 大纲脚本Agent（src/agents/outlineScript/index.ts）

**类名**：`OutlineScript`
**主控工具**：

| 工具名 | 职责 |
|--------|------|
| `AI1`（故事师） | 分析小说原文→生成故事线，调用`saveStoryline` |
| `AI2`（大纲师） | 故事线→生成剧集大纲，调用`saveOutline` |
| `director`（导演） | 审核故事线和大纲，调用`updateOutline`/`saveStoryline` |
| `getChapter` | 批量获取小说章节原文 |
| `saveOutline` / `updateOutline` / `deleteOutline` | 大纲CRUD |
| `generateAssets` | 从大纲自动提取角色/道具/场景资产 |

**核心Schema（Zod）**：`episodeSchema`

```typescript
const episodeSchema = z.object({
  episodeIndex: z.number(),              // 集数索引，从1开始
  title: z.string(),                     // 8字内，含情绪爆点
  chapterRange: z.array(z.number()),      // 关联章节号
  scenes: z.array(sceneItemSchema),       // 场景列表
  characters: z.array(characterItemSchema), // 角色列表
  props: z.array(propItemSchema),         // 道具列表（至少3个）
  coreConflict: z.string(),              // 核心矛盾：A想要X vs B阻碍X
  outline: z.string(),                   // 100-300字剧情主干（最高优先级）
  openingHook: z.string(),               // 开场镜头（outline第一句的视觉化）
  keyEvents: z.array(z.string()).length(4), // [起, 承, 转, 合]
  emotionalCurve: z.string(),             // 情绪曲线，如：2→5→9→3
  visualHighlights: z.array(z.string()),  // 3-5个标志性镜头
  endingHook: z.string(),                 // 结尾悬念（勾引下集）
  classicQuotes: z.array(z.string()),    // 1-2句金句（≤15字/句）
});
```

**三Agent职责链**：
```
用户输入 → 主Agent（outlineScript-main）
           ├→ AI1（故事师）→ 分析小说 → saveStoryline
           ├→ AI2（大纲师）→ 生成大纲 → saveOutline
           └→ director（导演）→ 审核修改 → updateOutline
```

### 2. 故事板Agent（src/agents/storyboard/index.ts）

**类名**：`Storyboard`
**主控工具**：

| 工具名 | 职责 |
|--------|------|
| `segmentAgent`（片段师） | 剧本→生成片段，调用`updateSegments` |
| `shotAgent`（分镜师） | 片段→生成分镜，调用`addShots`/`updateShots`/`deleteShots` |
| `generateShotImage` | 调用生成图+宫格切割+OSS上传（异步，后台执行） |
| `getScript` | 获取剧本内容 |
| `getAssets` | 获取资产列表（角色/道具/场景） |
| `getSegments` | 获取已生成的片段 |

**核心数据结构**：

```typescript
interface Segment {
  index: number;
  description: string;
  emotion?: string;   // 情绪氛围
  action?: string;    // 主要动作
}

interface Shot {
  id: number;                    // 分镜独立ID
  segmentId: number;             // 所属片段ID
  title: string;
  cells: Array<{
    id: string;      // 镜头唯一ID
    prompt?: string; // 镜头提示词
    src?: string;    // 生成图URL
  }>;
  fragmentContent: string;       // 关联片段描述
  assetsTags: Array<{ type: 'role'|'props'|'scene'; text: string }>;
}
```

**工作流**：
```
用户对话 → 主Agent（storyboard-main）
           ├→ segmentAgent → getScript/getAssets → updateSegments
           └→ shotAgent → getSegments → addShots/updateShots
                                         ↓
                              generateShotImage（异步）
                                   ├→ generateImageTool（宫格生成）
                                   ├→ imageSplitting（sharp切割）
                                   └→ u.oss.writeFile（OSS保存）
```

### 3. 分镜Prompt生成（src/agents/storyboard/generateImagePromptsTool.ts）

**函数**：`generateGridPrompt(options: GridPromptOptions)`
**输入**：prompts数组 + style + aspectRatio + assetsName
**输出**：`{ prompt: string; gridLayout: GridLayoutResult }`

**宫格布局算法**：

| 镜头数 | 布局 | 说明 |
|--------|------|------|
| 1 | 1x1 | 单格 |
| 2 | 2x1 | 横排双格 |
| 3 | 3x1 | 横排三格 |
| 4 | 2x2 | 四宫格 |
| 5-9 | 3x3 | 九宫格 |
| 10+ | 3行递增 | 每增3格+1行 |

**Prompt组装流程**：
1. 提取各镜头分镜描述
2. 按宫格位置编号（`[第N行第M列]: 描述`）
3. 注入资产映射（`人物=图片1, 场景=图片2`）
4. LLM优化风格一致性
5. 输出完整宫格图Prompt

---

### 4. 分镜图生成（src/agents/storyboard/generateImageTool.ts）

**函数**：`async (cells, scriptId, projectId) => Buffer`

**关键处理流程**：
1. 读取项目资产（角色/场景/道具图片）
2. **AI过滤相关资产**：LLM根据分镜描述筛选匹配的资产（避免无关资产干扰）
3. 构建资产映射Prompt（`角色A=图片1，场景B=图片2`）
4. 合并分镜Prompt + 资产图 + 风格参数 → AI绘图API
5. 返回宫格图Buffer

**图片预处理（防止API大小限制）**：
- 图片上限：10张，超出合并
- 单张上限：3MB（sharp jpeg压缩）
- 总量上限：10MB（按大小降序压缩）
- 超出宽高自动resize

### 主入口（src/utils/ai/generateVideo.ts）

**统一入口函数**：
```typescript
export default async (config: VideoConfig, manufacturer: string) => {
  // 1. 校验图片
  if (!config.imageBase64 || config.imageBase64.length <= 0) throw new Error("未传图片");

  // 2. 获取厂商配置（apiKey/baseURL/model）
  const configItem = await u.getConfig("video", manufacturer);
  if (!configItem) throw new Error("未找到任何视频配置");

  // 3. 双重重试
  for (let attempt = 0; attempt < 2; attempt++) {
    try {
      const videoUrl = await generateVideoWithConfig(config, configItem);
      // 4. 下载视频流 → OSS写入
      const response = await axios.get(videoUrl, { responseType: "stream" });
      await u.oss.writeFile(config.savePath, response.data);
      return config.savePath;
    } catch (error) { /* 重试 */ }
  }
  throw new Error("所有视频配置都失败了");
}
```

### 核心轮询函数

```typescript
const pollTask = async (
  queryFn: () => Promise<{ completed: boolean; imageUrl?: string; error?: string }>,
  maxAttempts = 500,
  interval = 2000,
): Promise<string> => {
  for (let i = 0; i < maxAttempts; i++) {
    await sleep(interval);
    const result = await queryFn();
    if (result.completed && result.imageUrl) return result.imageUrl;
    if (result.error) throw new Error(result.error);
  }
  throw new Error("任务轮询超时");
}
```

### 各厂商实现差异

| 厂商 | 端点 | 图片上传 | 轮询方式 | 特色 |
|------|------|---------|---------|------|
| volcengine | ARK API | base64直传 | GET任务状态 | 支持音频生成 |
| kling | Kling API | 纯base64（去data prefix） | GET任务状态 | STD/PRO双模式 |
| runninghub | OpenAPI v2 | 先上传到media API | POST查询输出 | 仅10/15秒 |
| openai | OpenAI API | 先上传到videos端点 | GET任务状态 | Sora 2 |
| apimart | APIMart API | 先预签名上传到CDN | GET任务状态 | Sora路由 |

## 本地存储（src/utils/oss.ts）

**类名**：`OSS`
**实现**：本地文件存储（兼容Electron/Node双模式）

| 方法 | 职责 |
|------|------|
| `getFileUrl(path)` | 返回本地HTTP服务URL（`http://127.0.0.1:60000/`） |
| `getFile(path)` | 读取文件为Buffer |
| `getImageBase64(path)` | 读取图片为base64 Data URL（含MIME类型推断） |
| `writeFile(path, data)` | 写入文件（自动创建父目录） |
| `deleteFile(path)` | 删除文件 |
| `deleteDirectory(path)` | 删除目录树 |
| `fileExists(path)` | 检查文件是否存在 |

**路径安全**：使用`isPathInside`校验，禁止路径穿越攻击。

**Electron适配**：Electron环境下使用`app.getPath('userData')`作为存储根目录，Node环境使用`process.cwd()/uploads`。

## 典型执行流程

```
1. 用户上传小说小说 → OutlineScript Agent
   └→ AI1生成故事线 → saveStoryline
   └→ AI2生成大纲 → saveOutline
   └→ generateAssets → 自动提取角色/场景/道具资产

2. 用户触发分镜 → Storyboard Agent
   └→ segmentAgent → updateSegments（片段拆分）
   └→ shotAgent → addShots（分镜+镜头Prompt）

3. 用户生成分镜图
   └→ generateImageTool
        ├→ AI过滤相关资产
        ├→ generateGridPrompt → 宫格Prompt
        ├→ AI绘图API → 宫格图Buffer
        └→ imageSplitting → 单格图Buffer[]
        └→ u.oss.writeFile → 各镜头发图

4. 用户生成视频
   └→ generateVideo（统一入口）
        ├→ 选厂商 → u.getConfig("video", manufacturer)
        ├→ generateVideoWithConfig
        │    ├→ volcengine/kling/runninghub/openai/apimart
        │    ├→ 图片上传（如需）
        │    └→ pollTask轮询
        └→ 下载视频流 → u.oss.writeFile
```

## 评级与使用建议

**执行层级**：A级
**代码质量**：高（TypeScript + Zod + Vercel AI SDK）
**可复用度**：高（适配器架构可直接移植）

**可直接复用**：
1. `src/utils/ai/video/` 适配器 → 扩充多平台支持（如扩充Kling/Seedance）
2. `src/agents/storyboard/generateImagePromptsTool.ts` → 分镜Prompt生成逻辑
3. `src/agents/storyboard/imageSplitting.ts` → 宫格切割（Sharp）
4. `src/utils/oss.ts` → 本地开发调试存储
5. `generateAssets`自动提取逻辑 → 漫舟Step 5资产库构建

**核心借鉴点**：
- **AI资产过滤**（filterRelevantAssets）：分镜级资产精准匹配，避免风格漂移
- **Episode Schema**：14字段大纲结构，比漫舟YAML更结构化
- **三Agent职责链**：AI1(故事)/AI2(大纲)/Director(审核)分工清晰
- **双重重试机制**：视频生成失败自动重试1次
- **宫格图策略**：多镜头合并生成，节省API调用成本

**漫舟整合建议**：
- 将`generateImagePromptsTool`宫格Prompt逻辑整合到`manzhou-shot-script.md`
- 将`filterRelevantAssets`逻辑整合到漫舟Step 6（资产就绪）流程
- `Episode`Schema可作为漫舟`IP档案.yaml`的参考数据结构
