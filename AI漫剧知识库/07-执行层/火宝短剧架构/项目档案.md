# 火宝短剧架构 · 项目档案

## 基础信息

- **来源**: huobao-drama-master（GitHub: chatfire-AI/huobao-drama）
- **技术栈**: Go 1.23+ · Gin · GORM · SQLite · FFmpeg
- **架构模式**: DDD（领域驱动设计）
- **执行层级**: A级（Go全栈，可直接参考API客户端封装）

## API接口体系

### 核心Handler（api/handlers/）

#### 剧本生成 API
- **文件**: script_generation.go
- **路由**: `POST /api/v1/generation/characters`
- **请求体**:
  ```go
  type GenerateCharactersRequest struct {
      DramaID     string  `json:"drama_id"`
      EpisodeID   uint    `json:"episode_id"`
      Outline     string  `json:"outline"`
      Count       int     `json:"count"`
      Temperature float64 `json:"temperature"`
      Model       string  `json:"model"`
  }
  ```
- **返回**: task_id（异步任务ID）

#### 角色管理 API
- **文件**: character_library_gen.go / character_library.go
- **核心路由**:
  - `POST /api/v1/character-library` — 添加到角色库
  - `GET /api/v1/character-library` — 列出角色库
  - `POST /api/v1/characters/batch-generate-images` — 批量生成角色形象
  - `POST /api/v1/characters/:id/generate-image` — 单角色生成形象
  - `PUT /api/v1/characters/:id/image` — 上传角色图片
  - `POST /api/v1/characters/:id/add-to-library` — 角色加入角色库
  - `POST /api/v1/episodes/:episode_id/characters/extract` — 从剧本提取角色

#### 分镜 API
- **文件**: storyboard.go
- **核心路由**:
  - `POST /api/v1/episodes/:episode_id/storyboards` — 生成分镜（异步）

## 应用服务编排（application/services/）

### 分镜编排服务 — storyboard_service.go

**核心方法**: `GenerateStoryboard(episodeID, model)`
**流程**:
1. 加载剧本内容 ScriptContent
2. 查询已提取的角色列表（Character）和场景背景（Scene）
3. 构建系统提示词（含角色/场景约束）+ 用户提示词（含详细分镜规范）
4. 创建 AsyncTask → 异步执行
5. LLM生成 JSON 分镜数组（支持数组和对象两种格式）
6. 事务保存到 Storyboard 表（先删后插）
7. 每条 Storyboard 自动生成两个专用提示词：
   - `ImagePrompt`: 首帧静态画面（去除动作过程）
   - `VideoPrompt`: 视频提示词（包含运镜/对话/氛围）

**分镜时长估算规则**:
- 基础时长: 对话4s / 动作5s / 混合6s
- 对话调整: +1-6s（按字数）
- 动作调整: +0-4s（按复杂度）
- 结果范围: 4-12秒

### 视频生成服务 — video_generation_service.go

**核心方法**: `GenerateVideo(request)` + `ProcessVideoGeneration(videoGenID)`

**完整流程**:
1. 接收 GenerateVideoRequest（支持4种参考图模式）
2. 保存 VideoGeneration 记录，状态=pending
3. 启动 goroutine 异步处理
4. `getVideoClient(provider)` — 根据provider路由到具体客户端
5. 本地图片 → Base64编码 → 传入API
6. 添加约束提示词（prompt_i18n）：包含运镜/时长/比例指令
7. `client.GenerateVideo()` — 提交生成任务，获取 task_id
8. 更新DB: task_id + status=processing
9. 启动 goroutine `pollTaskStatus()` 轮询
   - 间隔: 10秒，最大300次（约50分钟）
   - 完成后: 下载视频到本地 → 保存local_path → 更新storyboard.video_url
10. `RecoverPendingTasks()` — 服务启动时恢复 pending 状态任务

**客户端路由**:
```go
switch config.Provider {
case "chatfire":   return NewChatfireClient(...)
case "doubao", "volcengine":  return NewVolcesArkClient(...)
case "openai":     return NewOpenAISoraClient(...)
case "runway":     return NewRunwayClient(...)
case "pika":       return NewPikaClient(...)
case "minimax":    return NewMinimaxClient(...)
}
```

### 视频合并服务 — video_merge_service.go

**核心方法**: `MergeVideos(req)` + `FinalizeEpisode(episodeID, timeline)`

**FinalizeEpisode 流程**（时间线合成）:
1. 加载 Episode 及其关联的 Storyboard
2. 遍历 TimelineClip：
   - 优先从素材库（Asset）获取视频 → 使用 local_path
   - 次优先从 VideoGeneration 获取 local_path
   - 回退到 Storyboard.VideoURL
3. 按 order 排序，构建 SceneClip 数组
4. 调用 `mergeVideoClips()` 执行 FFmpeg 合并
5. 更新 Episode 状态=completed + video_url

### 角色生成服务 — character_library_service.go

**核心方法**:
- `GenerateCharacters()` — LLM从剧本提取角色列表
- `GenerateCharacterImage()` — AI图生角色形象

#### mergeWithXfade — 转场合并
```go

```
**完整流程**:
1. 检测每个视频的音频流 + 分辨率
2. 统一缩放到最大分辨率（添加黑边 pad）

4. 构建 xfade 滤镜链（支持25种转场类型）
5. 音频使用 acrossfade 交叉淡入淡出

## 存储架构（infrastructure/storage/local_storage.go）

- **本地存储根目录**: `./data/storage/`
- **静态资源URL**: `http://host:port/static/`
- **目录结构**:
  ```
  data/storage/
  ├── images/          # 生成图片
  ├── videos/          # 生成视频
  │   └── merged/     # 合并后视频
  ├── video_frames/    # 视频首帧缓存
  └── audios/          # 提取的音频
  ```
- **Base64策略**: 本地图片先转Base64再发给AI API；AI返回的URL下载到本地
- **相对路径**: 数据库存储相对于storage根目录的路径（如 `images/xxx.jpg`）

### 模式3：任务轮询
```go
func (s *VideoGenerationService) pollTaskStatus(videoGenID uint, taskID string, ...) {
    maxAttempts := 300
    interval := 10 * time.Second
    for attempt := 0; attempt < maxAttempts; attempt++ {
        time.Sleep(interval)
        result, err := client.GetTaskStatus(taskID)
        if result.Completed {
            s.completeVideoGeneration(videoGenID, result.VideoURL, ...)
            return
        }
        if videoGen.Status != "processing" { // 手动取消检查
            return
        }
    }
    s.updateVideoGenError(videoGenID, "polling timeout")
}
```

```go
f.mergeWithXfade(trimmedPaths, clips, outputPath)
```

### 模式6：本地图片Base64上传
```go
func (s *VideoGenerationService) convertImageToBase64(imageURL string) (string, error) {
    if strings.HasPrefix(imageURL, "data:") { return imageURL, nil } // 已是Base64
    // 优先读本地文件
    if strings.Contains(imageURL, "/static/") {
        relPath := extractRelativePath(imageURL)
        absPath := localStorage.GetAbsolutePath(relPath)
        return utils.ImageToBase64(absPath)
    }
    // 回退：从URL下载
    return utils.ImageToBase64(imageURL)
}
```

### 模式7：异步任务+进度更新
```go
func (s *TaskService) UpdateTaskStatus(taskID, status string, progress int, message string) error {
    updates := map[string]interface{}{
        "status": status, "progress": progress, "message": message,
        "updated_at": time.Now(),
    }
    if status == "completed" || status == "failed" {
        now := time.Now()
        updates["completed_at"] = &now
    }
    return s.db.Model(&AsyncTask{}).Where("id = ?", taskID).Updates(updates).Error
}
```

## 评级与使用建议

**执行层级**: A级
**可复用度**: 高（Go全栈，API客户端封装可直接移植）

**关键借鉴点**:
1. **多AI视频客户端接口抽象 + Provider路由** — 5个平台统一接口，热插拔切换
2. **参考图模式设计** — single/first_last/multiple/none 覆盖所有图生视频场景
3. **FFmpeg在Go中的完整封装** — 合并/裁剪/转场/音频提取全部实现
4. **异步任务状态机** — UUID任务ID + 进度0-100 + 多格式结果存储
5. **DDD分层架构** — domain/models（数据）+ application/services（编排）+ infrastructure（外部依赖）
6. **分镜双提示词策略** — ImagePrompt（静态）+ VideoPrompt（动态运镜）分离生成
7. **服务启动恢复机制** — RecoverPendingTasks 保证断线重连不丢任务
8. **Base64本地中转** — 解决本地文件无法直接发给AI API的问题

**与LibTV/ZJT的差异**:

| 维度 | 火宝短剧 | LibTV | ZJT |
|------|---------|-------|-----|
| 语言 | Go | TypeScript | TypeScript |
| 视频客户端 | 5个平台（MiniMax/Sora/Seedance/Runway/Pika） | 较少 | 较多 |
| FFmpeg | 完整封装含转场 | 无 | 无 |
| 异步任务 | UUID+进度+结果JSON | 无 | 无 |
| 架构 | DDD | 简单分层 | Multi-Agent |
| 分镜生成 | LLM JSON直接输出 | 模板 | 模板+LLM |
| 参考图模式 | 4种（单图/首尾帧/多图/无） | 较少 | 较少 |
