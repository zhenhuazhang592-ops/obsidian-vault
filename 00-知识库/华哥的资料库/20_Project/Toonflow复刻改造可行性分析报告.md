# Toonflow复刻改造可行性分析报告

**报告日期**: 2026-03-17
**报告性质**: 内部可行性分析
**项目名称**: AI科普视频创作工具

---

## 一、项目背景

### 1.1 原项目概况

- **项目名称**: Toonflow-app
- **GitHub**: HBAI-Ltd/Toonflow-app
- **Stars**: 4677
- **技术栈**: Electron + TypeScript + Express + SQLite + 多种AI SDK
- **应用类型**: 桌面端AI视频生成应用

### 1.2 改造目标

将Toonflow-app从桌面端应用改造为Web端的"AI科普视频创作工具"，实现：

- **输入**: 科普文章（文字）
- **输出**: 科普视频（形象+配音+字幕+音画同步）
- **部署方式**: 网页端（Vercel + 免费额度）
- **目标用户**: 科普作家、教师、科研机构、自媒体创作者

### 1.3 已确定的AI模型组合（性价比方案）

| 能力 | 模型 | 预计成本 |
|------|------|----------|
| LLM | 通义千问 Turbo | ¥0.5/次 |
| 图像 | 通义万相 WanX | ¥2-4/张 |
| 视频 | 快手可灵 KLING | ¥5-8/分钟 |
| TTS | 通义语音 | ¥1-2/分钟 |
| **合计** | | **¥7-14/分钟视频** |

## 二、原项目代码可复用性分析

### 2.1 可复用部分（30-40%）

| 模块 | 可复用程度 | 说明 |
|------|------------|------|
| AI SDK集成层 | 高 | 多种AI API调用封装、错误处理、重试机制可直接迁移 |
| 任务队列管理 | 中 | 视频生成的异步任务调度逻辑可参考 |
| 文件处理模块 | 中 | 素材上传、存储、格式转换等通用功能可复用 |
| 基础UI组件 | 中低 | 桌面组件需适配Web端，参考价值有限 |
| 配置管理 | 高 | 环境配置、密钥管理等模式可复用 |

### 2.2 需要重写部分（60-70%）

| 模块 | 重写原因 | 工作量评估 |
|------|----------|------------|
| 核心业务流程 | 从"文字转视频"到"科普文章转视频"逻辑完全不同 | 高 |
| 用户界面 | 桌面应用 → Web应用，需全新设计 | 高 |
| 数据模型 | 用户管理、作品管理、素材库结构需重新设计 | 中 |
| AI提示词工程 | 科普视频生成需要全新的Prompt模板体系 | 高 |
| 认证授权 | 桌面端无用户系统，Web端需全新开发 | 中 |

### 2.3 复用策略建议

**推荐策略**: "架构参考 + 核心代码重写"

- 复用AI集成层的技术架构思路
- 复用任务队列设计模式
- 核心业务逻辑和UI全部重写
- **综合成本约为全新开发的70%**，性价比高

### 3.2 技术选型

| 层级 | 推荐方案 | 理由 |
|------|----------|------|
| 前端框架 | Next.js 14 + React | Vercel原生支持，SSR/SSG灵活 |
| 后端框架 | Next.js API Routes | 轻量级首选，Vercel免费额度内 |
| 数据库 | PostgreSQL (Supabase) | 免费额度大，支持向量搜索 |
| 对象存储 | AWS S3 / 阿里云OSS | 视频文件存储 |
| 部署平台 | Vercel | 免费额度充足，月$0起 |
| 用户认证 | NextAuth.js | 简单易用，支持多提供商 |
| 状态管理 | Zustand | 轻量级，易上手 |
| UI组件库 | Tailwind CSS + shadcn/ui | 现代Web标准 |

### 10.2 内容创作建议

**黄金3秒开头**：

- 颠覆认知："其实我们都错了..."
- 数据吸睛："90%的人都搞错了！"
